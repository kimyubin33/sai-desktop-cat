# Windows 데스크톱을 사이 팀 서버로 쓰기

이 문서는 지정한 PC 한 대를 기존 팀 서버로 사용하는 방식입니다. v0.9.14의 별도 **Drive → PC 톡**은 외부 조정 서비스나 별도 VPN 앱 없이 같은 LAN의 승인 장치끼리 연결하는 준비 기능이며, 아래 서버 설치 절차와 구분합니다. [자동 호스트 설계](automatic-host-design.md)와 [PC 톡 사용 흐름·구현 범위](mesh-automatic-connection.md#10-대화-화면의-pc-톡과-작성-장치의-삭제-요청)를 참고하세요. 기존 팀 기록을 자동 전환하지 않습니다.

서버를 운영할 인텔·AMD Windows 데스크톱 한 대와 팀원의 사이 앱이 필요합니다. 팀 톡, 약속, 프로젝트와 승인된 개인 조언은 데스크톱의 SQLite 파일에 저장됩니다. 파일 공유는 각 팀원의 Google Drive를 계속 사용합니다. 개인 상담 원문과 개인 Claude·GPT 키는 각자의 PC에 남습니다.

## 1. 데스크톱에서 서버 실행

Google Drive·캘린더는 각 PC에서 Google에 직접 연결하므로 이 팀 서버가 꺼져 있어도 사용할 수 있습니다(인터넷과 Google 로그인은 필요합니다). 팀 톡 전송, 새 팀 기록 조회와 파일 링크의 팀 공유는 서버가 실행 중일 때 가능합니다. 서버에 연결되지 않으면 이전에 읽은 톡·파일 목록을 표시하며, 보내기에 실패한 내용은 전송 완료로 처리하지 않습니다.

1. 사이 릴리스에서 `Sai-Team-Server-버전-win-x64.zip`을 받습니다. 다운로드 폴더에서 ZIP을 **모두 압축 풀기**로 풀고, 앞으로 계속 사용할 폴더에 둡니다. 팀원 PC에는 같은 릴리스의 일반 사이 앱을 설치하거나 자동 업데이트를 적용합니다.
2. 데스크톱의 `Start.cmd`를 두 번 클릭하고 **1. 서버 실행**을 선택합니다. 메뉴를 닫아도 별도의 서버 창이 계속 실행됩니다. 서버를 멈출 때는 서버 창에서 Ctrl+C를 누릅니다.
3. 메뉴의 **2. 서버 상태 확인**을 선택합니다. 브라우저에서 `http://127.0.0.1:8765/health`를 열어도 됩니다. 응답의 `service`가 `sai-team-server`, `projectId`가 `saigajoa`인지 확인합니다.
4. **5. 로그인 시 자동 시작 설정 → 1**을 선택하면 해당 Windows 사용자가 로그인할 때 같은 서버가 시작됩니다. 데스크톱이 깨어 있고 인터넷에 연결돼 있어야 팀원이 동기화할 수 있습니다. Windows를 다시 시작한 뒤에는 해당 계정에 한 번 로그인합니다.

## 2. 기존 방 복사

**기존 앱에서 먼저** 팀 이름, 여섯 자리 참여 코드, 참여 중인 다른 방을 확인합니다. 함께 옮길 기존 방은 전부 복사합니다. 복사를 시작하기 전에 팀원들에게 기존 방의 톡·파일·업무 입력을 잠시 멈춰 달라고 하고, 모두 데스크톱 주소로 바꿀 때까지 기다립니다. 복사 뒤 기존 Firebase에 새로 입력한 내용은 자동으로 따라오지 않습니다. **정리함 → 공유 대기함**에서 보내야 할 문안이 이전 서버로 전송됐는지 먼저 확인하세요. 새 서버로 처음 전환할 때 확인된 방의 대기 문안과 팀 캐시는 한 번 복사되고, 원래 서버의 대기함도 따로 보존됩니다. 같은 문안을 양쪽 서버에서 보내는 일을 피하려면 전환 후에는 한 서버를 계속 사용하세요. 옮기지 않은 방의 대기 항목은 원래 서버에 남습니다. 각자의 Google 로그인과 기기에 저장된 개인 상담 기록은 그대로 사용할 수 있습니다.

1. 서버 데스크톱에 Google Cloud CLI를 설치합니다. 새 터미널에서 `gcloud auth login`을 실행하고 브라우저에서 **saigajoa 프로젝트의 Firestore 데이터를 읽을 수 있는 본인 Google 계정**을 선택합니다. 기존 프로젝트 소유자나 Cloud Datastore Viewer 권한을 가진 계정을 사용할 수 있습니다. 로그인 정보와 토큰은 이 컴퓨터에서만 다룹니다. [Windows 설치](https://cloud.google.com/sdk/docs/install#windows) · [Google 계정 로그인 안내](https://cloud.google.com/sdk/docs/authenticate)
2. `Start.cmd`에서 **3. 기존 Firebase 팀 복사**를 선택해 참여 코드를 입력합니다. 설치나 로그인을 아직 하지 않았다면 메뉴에서도 공식 설치 페이지와 Google 로그인을 열 수 있습니다. 여러 방은 공백으로 구분합니다. 원하는 팀만 골라 복사하므로 다른 방이나 테스트 방을 넣지 않아도 됩니다.
3. 복사 완료와 문서 수를 확인합니다. 읽기 한도(429)나 권한 오류가 나오면 기존 Firebase 연결을 유지하고, 원인이 해소된 후 같은 코드로 다시 실행합니다. 원본은 그대로 유지되고, 기존 로컬 팀과 충돌하면 덮어쓰기를 중단합니다.

복사한 팀의 기존 계정과 팀 ID를 유지하므로 현재 사이 계정을 그대로 사용하세요. 새 PC에 이전 Firebase 팀의 Google 백업만 있다면 기본 Firebase 연결에서 팀 계정을 먼저 복원한 뒤 데스크톱 주소로 전환합니다. 완전히 새 팀을 만들려면 팀 개설자가 앱의 **설정 → 팀 연결 → 팀 서버 선택 → 내 팀 계정 ID 확인**에서 UID를 복사해 서버 관리자에게 알려 줍니다. 관리자는 서버 메뉴 **6. 새 팀 개설자 등록**에 이 UID를 입력합니다. 팀 참여 코드와 계정 UID는 서로 다른 값입니다.

## 3. 다른 팀원에게 닿는 HTTPS 주소 만들기

### 팀 전용 네트워크 사용

1. 데스크톱과 팀원 PC에 Tailscale을 설치하고 각자 로그인합니다. 서버를 사용할 팀원을 같은 Tailscale 네트워크에 초대하거나 데스크톱 장치만 공유합니다. 팀원의 장치가 데스크톱의 HTTPS 서비스에 접근할 수 있어야 합니다. [팀원 초대](https://tailscale.com/docs/features/sharing/how-to/invite-team-members) · [장치 공유](https://tailscale.com/kb/1084/sharing)
2. 데스크톱에서 **Start.cmd → 8. 팀원용 HTTPS 주소 설정 (Tailscale)**을 선택합니다. 안내된 내용을 확인하고 **1**을 입력한 후 Windows 권한 요청을 승인합니다. 최초 설정에서 Tailscale이 표시하는 링크를 따라 HTTPS 인증서를 활성화합니다. 메뉴가 기존 Tailscale 서비스를 발견하거나 직접 연결하려면 **터미널(관리자)**에서 서비스 사용 현황을 확인해 다음 명령을 진행합니다.

   ```powershell
   tailscale serve --bg http://127.0.0.1:8765
   tailscale serve status
   ```

3. 출력에 나오는 `https://…ts.net` 주소를 팀원에게 전달합니다. 팀원 PC에서 Tailscale에 연결한 상태로 주소 뒤에 `/health`를 붙여 열고 사이 서버 응답을 확인합니다. 접속할 때 데스크톱과 팀원 PC 양쪽에서 Tailscale이 작동해야 합니다. [Tailscale Serve 안내](https://tailscale.com/docs/features/tailscale-serve)

### 이미 Cloudflare에서 관리하는 도메인이 있는 경우

팀원들에게 별도 네트워크 프로그램을 설치하지 않으려면 Cloudflare의 고정 호스트 이름을 연결할 수 있습니다. Cloudflare 대시보드에서 **Networking → Tunnels → Create Tunnel**을 선택합니다. Windows용 연결 절차를 서버 데스크톱에서 진행하고, **Routes → Add route → Published application**에 보유 도메인의 이름과 원본 서비스 `http://127.0.0.1:8765`를 지정합니다. 터널 토큰은 서버 데스크톱에서만 사용하고, 팀원에게는 완성된 HTTPS 주소만 전달합니다. 이 주소는 인터넷에서 접속할 수 있으므로 프로젝트 로그인과 서버의 팀별 권한 검사가 적용됩니다. [Cloudflare Tunnel 설정](https://developers.cloudflare.com/tunnel/get-started/)

## 4. 팀 앱을 함께 전환

1. 팀원들은 기존 사이 계정으로 **설정 → 팀 연결 → 팀 서버 선택**을 엽니다. 팀원 PC에는 위의 HTTPS 주소를 입력합니다. 서버 데스크톱에서는 **이 PC 주소 넣기**를 눌러 `http://127.0.0.1:8765`를 사용할 수 있습니다. 주소 입력란에는 `/health`를 붙이지 않습니다.
2. **연결 확인 → 이 서버 사용**을 누르고 운영자가 안내한 주소인지 확인합니다. 이어서 표시되는 연결할 팀과 기존 서버에 남는 팀을 확인하고 승인하면 사이가 다시 시작됩니다. 이용할 방이 빠졌다면 전환을 취소하고 2단계에서 먼저 복사하세요. 기존 서버를 다시 열려면 같은 설정의 **Firebase로 돌아가기**를 누릅니다.
3. 기존 팀원 둘이 같은 팀과 최근 기록을 확인합니다. 팀 톡 하나를 보내고, 다른 팀원이 받으면 전환을 마칩니다. 가입할 새 팀원은 동일한 서버 주소를 먼저 설정한 다음 기존 참여 코드로 들어옵니다. Firebase 사용자 인증과 Google Drive, Claude·GPT의 외부 서비스는 계속 인터넷을 사용합니다.

## 백업과 복구

팀 데이터는 서버를 실행하는 Windows 계정의 `%LOCALAPPDATA%\SaiTeamServer\team.sqlite3`에 있습니다. **4. 팀 데이터 백업**에서 저장 위치를 선택하면 실행 중인 서버도 일관된 SQLite 사본을 만들 수 있습니다. 데스크톱을 분실하거나 디스크가 고장 나는 경우에 대비하려면 백업을 해당 Windows 사용자만 접근하는 다른 드라이브에도 보관합니다. 데이터 파일과 백업에는 승인된 개인 조언, 팀에 공유한 연동 정보와 파일 링크가 들어 있습니다.

복구할 때는 실행 중인 서버 창을 모두 종료하고 `/health`가 응답하지 않는지 확인합니다. 기존 데이터 폴더의 `team.sqlite3`와 같은 이름으로 시작하는 `-wal`, `-shm` 파일을 발견하면 모두 별도의 폴더에 함께 보관합니다. 백업 사본을 원래 경로에 `team.sqlite3` 이름으로 복사한 다음 서버를 시작합니다. 복원 시점 이후에 쓴 기록은 이전에 보관한 폴더에서만 찾을 수 있습니다.

서버 실행 파일을 업데이트할 때도 먼저 서버를 멈추고 백업합니다. 새 ZIP을 풀어 서버를 실행하고, 위치를 옮겼다면 **5. 로그인 시 자동 시작 설정**에서 새 위치를 다시 등록합니다.
