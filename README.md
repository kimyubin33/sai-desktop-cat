# 사이 — 데스크톱 협업 도우미

사이는 **Google로 로그인해 팀 파일·업무·일정을 AI와 함께 정리하는 간단한 데스크톱 앱**입니다. 바탕화면의 반투명 검은 유리 불꽃을 누르면 개인 AI를 열 수 있습니다. 앱 로고는 AI와 사람을 잇는 무한대 모양입니다. 같은 Google 계정으로 다른 PC에서도 내 팀·이름·설정을 이어 쓰고, 파일과 협업 정보는 Google Drive로 공유하는 방향입니다.

Windows 설치판은 v1.0.1부터 새 v1 릴리스를 자동으로 확인하고 설치 파일을 내려받습니다. v1.0.0이나 기존 PC 톡에서 전환하는 경우 v1.0.1 설치 파일을 받아 한 번 직접 설치하세요. Google 로그인은 등록된 테스트 계정에서 확인했습니다. [사이 v1.0.1 다운로드](https://github.com/kimyubin33/sai-desktop-cat/releases/tag/v1.0.1)

**[사용 설명서](docs/user-guide.md)** — Google 로그인, 팀·파일·AI·내 일정의 사용법과 권한·자료 보관 범위를 정리했습니다. 앱 오른쪽 위 **?**에서도 열 수 있습니다.

[유리 화면 패치](docs/patches/2026-11-18-glass-workspace.md)에서 설명 위주의 화면을 짧은 이름과 아이콘으로 바꾸고, 물방울 모양의 버튼·반투명 유리 창·부드러운 전환을 적용했습니다. Windows x64 미리보기는 `target/Sai-Preview-Glass-20261118-win-x64.zip`으로 보관합니다. 상세 검증 범위와 남은 확인 사항은 패치 기록을 따릅니다.

**2026-11-17부터 후속 개발은 [개발 방향과 단계별 실행 계획](docs/development-direction.md)을 기준으로 진행합니다.** 팀원 간 톡·PC 서버·Firebase 의존과 공용 AI 키 배포를 정리하고, Google 계정 복원 → 파일·협업 → 팀 AI 중계 → 개인 Calendar 순서로 전환합니다. 일반 사용자에게 서버 설정을 요구하지 않습니다.

현재 작업본은 **1단계 정리와 로컬 검증을 마치고, 2~5단계 기본 경로를 구현해 6단계의 전체 흐름 점검을 진행하는 상태**입니다. 먹물 질감의 파일·협업·AI·설정 화면으로 바꾸고 톡·PC 연결·기존 서버 동기화 실행을 제거했습니다. 개인 대화 기록과 설정은 유지하며 이전 팀 자료는 원본을 두고 선택 사본으로 내보냅니다. Google 계정 설정·팀 복원·파일 전송·협업 변경 기록·AI 후보 검토와 본인 기본 Calendar의 일정 추가·수정·삭제를 연결했습니다. Windows 설치 기본 동작, 실제 Google 파일·협업·Calendar와 Claude 샘플 분석, 별도 계정의 팀 권한 회수 후 차단까지 확인했습니다. 승인한 앤드위브 AI 한 팀의 상시 연결을 하루 10회로 활성화했고 상태 조회·앱 표시를 확인했습니다. 다른 PC·새 설치·다른 역할·실제 팀원 분석과 운영 지속성 검증은 남아 있습니다. ### 기존 릴리스 기록: v0.9.14 — PC 톡 준비 기능

**Drive → PC 톡**에서 관리자 한 명이 승인한 PC 장치끼리 톡을 주고받을 수 있습니다. 새 톡은 이 PC에 먼저 보호해 저장하고, 같은 LAN의 승인 PC와 암호화해 교환합니다. 상대 저장 확인, 작성 장치가 서명한 삭제 요청, 암호문 중계와 현재 연결 범위의 대표 PC 선정, 선택한 Windows 네트워크에서의 별도 자동 복구를 제공합니다. 외부 조정 서비스나 별도 VPN 앱을 추가하지 않습니다.

기록 교환에 사용할 **모든 PC를 새 버전으로 업데이트하고 연결 정보를 다시 생성**해야 합니다. 현재는 같은 Wi-Fi·유선 LAN과 동의한 최대 15분 실행을 지원하는 준비 기능입니다. 실제 여러 PC의 설치·화면·절전 검증과 서로 다른 인터넷 환경의 자동 연결은 남아 있습니다. 기존 서버 톡·계정 이름·과거 기록은 자동 전환하지 않으며, 기존 공개 톡의 선택 보관은 관리자 PC 전용 사본입니다. [설정·사용 흐름과 구현 범위](docs/mesh-automatic-connection.md#10-대화-화면의-pc-톡과-작성-장치의-삭제-요청), [연결 진단 실행 파일 만들기](docs/mesh-connection-experiment.md)를 참고하세요.

## 기술 구성

**Tauri 2 + Rust**로 만듭니다. Google·파일·협업·AI·일정·저장 로직은 Rust(`core/`, `src-tauri/`), 화면 동작은 Rust/Wasm(`ui-app/`), 레이아웃은 HTML·CSS(`ui/`)입니다. Windows에서는 WebView2로 화면을 그립니다. 공용 Claude 키를 보호하는 중계 소스는 `services/team-ai/`에 있으며 현재 승인한 한 팀의 상시 연결을 활성화했습니다.

## 실행

Rust(rustup, `rustup target add wasm32-unknown-unknown`)와 Node.js(Tauri 빌드 도구용)가 필요합니다. 앱 화면은 Rust로 작성해 WebAssembly 로 만듭니다 (`cargo run -p xtask -- ui`, 빌드할 때 자동 실행).

```bash
npm ci               # Tauri 빌드 도구 설치
npm run dev          # 개발 실행
npm test             # 핵심 로직 테스트 (cargo test --workspace)
node --test services/team-ai/gateway.test.mjs scripts/check-google-client.test.mjs scripts/build-preview.test.mjs
node scripts/check-google-client.mjs  # 개발 측 연결 정보의 형식 확인 (내용 출력 없음)
npm run build:preview # 현재 전환 중인 검증 설치 파일 만들기 (Windows)
```

ARM Windows에서 x64 개발 도구를 쓰는 현재 로컬 검증은 `cargo test --locked --workspace --target x86_64-pc-windows-msvc -- --test-threads=4`로 실행합니다. Firebase 실계정 검사는 과거 구현용이며 현재 Google 작업 공간의 검증 절차에 포함하지 않습니다.

### 전환 중 검증 설치 파일

PR과 `main` 소스 변경은 [Google 작업 공간 검사](.github/workflows/check-workspace.yml)로 Wasm·Rust·중계·빌드 설정 모의 검사를 실행합니다. Google 계정이나 유료 AI 연결은 사용하지 않습니다.

[Windows 검증 설치 파일](.github/workflows/build-windows.yml)은 개발자가 GitHub Actions에서 수동 실행합니다. 개발 측 `GOOGLE_CLIENT_JSON`이 없거나 데스크톱 앱 형식이 아니면 중단합니다. 중계가 준비됐다면 공개 원점만 `SAI_TEAM_AI_ENDPOINT` 저장소 변수로 제공합니다. 일반 사용자가 서버·JSON·공용 AI 키를 설정하지 않습니다. 자세한 형식은 [빌드 설정](config/README.md)을 따릅니다.

통과하면 CPU별 Actions 아티팩트에 `Sai-Preview-Setup-<버전>[-arm64].exe`, `Sai-Preview-Portable-<버전>[-arm64].exe`와 체크섬을 보관합니다. 정식 Windows 설치 파일에는 기본 Tauri 설정을 사용하며 [Releases](https://github.com/kimyubin33/sai-desktop-cat/releases)에 게시합니다.

검증판은 **사이 미리보기**라는 별도 앱으로 설치합니다. 앱 ID·실행 파일·자료 저장 공간·시작 메뉴가 기존 사이와 다르고, 시작 프로그램과 정식 자동 업데이트는 사용하지 않습니다. 로컬·CI 모두 `npm run build:preview`를 사용하며, 결과는 `target/preview-dist/win-x64` 또는 `win-arm64`에 모읍니다. ARM Windows에서 x64 도구로 빌드할 때는 `npm run build:preview -- --target x86_64-pc-windows-msvc --ui-host-target x86_64-pc-windows-msvc`를 사용합니다. 일반 `npm run build`는 기존 제품 설정으로 빌드하므로 전환 중 검증 배포에 사용하지 않습니다.

기존 PC 톡 설치판은 v0.9.14 자동 업데이트 채널을 사용합니다. [기존 PC 톡 릴리스](https://github.com/kimyubin33/sai-desktop-cat/releases/tag/v0.9.14)

## 이전 버전의 기능

**바탕화면 고양이 (1단계)**
- 작업 표시줄 위를 걷고, 앉고, 식빵 자세로 쉬고, 잠듭니다. 도트 그림은 코드로 그려서 외부 이미지가 없습니다.
- 회색 줄무늬 고양이를 천천히 끌어 놓으면 바닥으로 내려와 앉습니다. 다른 모니터로도 옮길 수 있습니다.
- 잡은 채로 빠르게 여러 번 흔들면 “어지러...”라고 합니다. 화면 가장자리로 세게 던져 부딪히면 “아야!” 하고 튕깁니다.
- 다른 팀원이 보낸 새 톡은 화면 오른쪽 위에서 얼굴을 내민 고양이가 보여 줍니다. 말풍선을 누르면 해당 팀의 톡이 열립니다.
- 고양이를 클릭하면 대화창, 오른쪽 클릭하면 메뉴가 열립니다. 투명한 부분은 클릭이 아래 창으로 통과합니다.
- 평소에 일상 한마디·생각거리·협업 조언·고전 문장을 말풍선으로 건넵니다.
  - 사이가 직접 쓴 문장은 `사이의 한마디`로, 고전·속담은 출전(예: 『논어』 위정편)으로 표시합니다. 출처가 불확실한 "유명인 명언"은 넣지 않았습니다.
- 말풍선마다 **닫기 · 나중에 · 이런 말 줄이기 · 이야기하기**가 있고, 최근 한 말은 반복하지 않습니다.
- 트레이·오른쪽 클릭 메뉴: 조언 한마디 듣기, 조용한 모드, 집중 모드(30분/1시간/2시간), 말 거는 빈도, 숨기기.
- 설정: 방해 금지 시간(자정 넘김 지원), "이런 말 줄이기" 기록 초기화.

**개인 대화 (2단계)**
- 대화 화면에서 **팀원 일로 속상해요**, **팀 약속 잡기**, 내 사정을 이야기하고 싶어요, 그냥 이야기할래요, 일정 조정하기를 고를 수 있습니다.
- 속상한 이야기는 `감정 알아주기 → 어떤 약속·기대였는지 → 서로 확인한 약속이었는지·상대 사정 → 실제 영향 → 바라는 것` 순서로 묻고 **정리 카드**를 만듭니다. "정리해 줘"라고 하거나 버튼으로 언제든 정리할 수 있고, 질문은 건너뛸 수 있습니다.
- 정리 카드: 내가 보고한 사건, 약속 확인 여부(추측은 추측으로 표시), 공동 기록 확인 여부, 감정, 영향, 필요, 가능한 행동 요청, **사람에 대한 평가를 행동으로 바꾼 표현**, 아직 확인할 점, 반영할 일반 주제. 직접 고칠 수 있습니다.
- 욕설·평가 표현은 정리 카드에 옮기지 않습니다.
- "죽고 싶다"처럼 긴급한 위험 신호가 보이면 흐름을 멈추고 안전 확인과 상담 전화(109, 1577-0199, 112·119)를 먼저 안내하며, 그 대화는 공유할 수 없게 막습니다. "힘들어 죽겠다" 같은 일상 표현은 위험 신호로 보지 않습니다.

**AI 공유 대기함과 팀 약속**

- **팀원 일로 속상해요**에서 이야기한 뒤 **AI 공유 문안 만들기**를 누릅니다. 정리 카드에서도 문안을 만들 수 있습니다. AI가 구체적인 행동을 제안할 수 있는지 판단해 개인 조언이나 팀 약속을 추천하고, 더 알아야 하면 질문합니다. 하소연만 하고 싶은 경우에는 대화를 비공개로 마칠 수 있습니다.
- **대화 → 팀 약속 잡기**에서는 팀 전체에 제안할 회의 일정이나 협업 방식을 대화로 작성합니다. 예를 들어 “주간 회의 전까지 안건을 한 곳에 모으고 싶어요”라고 시작할 수 있습니다. 제안 제목과 본문을 검토하고 승인하면 팀 톡에 올라가며, **정리함 → 팀 약속**에서 팀원이 응답합니다. 두 명 이상인 팀에서 전원이 동의하면 약속이 확정됩니다.
- 새 문안은 **설정 → AI 연결**에 등록한 Claude 또는 GPT로 작성합니다. 요청 중 연결이 끊기면 같은 대화에서 재시도할 수 있습니다. 작성한 초안 검토·승인, 대기 중인 항목 전송, 기존 약속에 응답할 때는 AI 호출이 필요하지 않습니다. 팀원에게 전달되려면 앱과 팀 서버가 연결되어 있어야 합니다.
- AI에 보내는 대화에서 앱이 아는 팀원 이름과 연락처 같은 식별 정보를 걸러냅니다. 개인 대화 기록은 이 기기에 저장되며, 팀에는 사용자가 확인한 문안만 전달됩니다. 소규모 팀에서는 일반화된 문안으로도 사정을 짐작할 수 있으니 보내기 전에 내용과 대상을 확인하세요.

**팀 연결 (3단계, Firebase)**
- 한 명이 팀을 만들고 6자리 참여 코드로 팀원이 들어옵니다. 계정은 익명 로그인이고, 로그인 정보는 각자 컴퓨터에 암호화해 둡니다.
- 개인 조언을 보내려면 받을 팀원을 직접 고릅니다. 승인한 개인 문안은 20분~3시간의 지연 후 동기화 때 전달됩니다. 받는 사람은 **정리함 → 받은 조언**에서 확인합니다. 팀 약속으로 승인한 제안은 다음 동기화 때 팀에 공유되며 팀 톡에서 작성자를 확인할 수 있습니다.
- 이전 버전에서 보낸 일반 주제도 수신·보류할 수 있습니다. 팀원에게서 받은 주제는 평소 고양이 조언에 반영됩니다. 보류한 주제에서 새 약속을 제안할 때에는 원래 팀의 약속 작성 화면을 엽니다.
- **정리함**에서 보내기 전 항목을 취소하고, 내가 보낸 개인 조언을 철회하거나 직접 제안한 팀 약속을 삭제할 수 있습니다. 받은 항목에서 **내 목록에서 삭제**를 선택하면 이 기기에서만 사라집니다.
- 개인 문안의 전달과 서버에서의 철회에는 저장소의 `firestore.rules` 게시가 필요합니다. 서버가 권한을 허용할 때까지 전송 대기 항목이 이 기기에 남습니다. 운영자는 [Firebase 설정 안내](docs/firebase-setup.md)에서 규칙 게시 방법을 확인할 수 있습니다.
- 설정에 팀 이름, 참여 코드, 팀원, 마지막 동기화 시각, 연결 오류를 그대로 보여 줍니다.
- 보안 규칙(`firestore.rules`): 팀원만 팀 데이터 접근, 받은 주제는 받는 사람만 목록 조회, 보류는 받는 사람만, 팀 약속 응답은 각자 자기 것만.
- Firebase 없이 한 컴퓨터에서 시험하는 **로컬 시험 모드**도 있습니다 (docs/firebase-setup.md 5절).

**여러 팀 (팀플이 여러 개일 때)**
- 설정 → 팀 연결에서 팀을 더 만들거나 참여 코드로 계속 추가할 수 있습니다. 팀마다 내 이름도 따로 정합니다.
- 대화창 위쪽 이름 아래의 팀 고르기로 **보고 있는 팀**을 바꿉니다. 협업 탭·정리함·공유 기본값이 그 팀을 따릅니다.
- 고민을 공유할 때 **어느 팀 이야기인지** 고르면, 받을 팀원 목록도 그 팀으로 바뀝니다. 주제는 그 팀에만 갑니다.
- 고양이 말풍선(받은 조언 주제, 팀 약속 제안, 진행 확인)은 **모든 팀을 함께** 봅니다. 팀이 둘 이상이면 출처 줄에 팀 이름이 붙습니다.
- 자기소개·가능 시간은 팀마다 따로입니다 (팀플마다 쓸 수 있는 시간이 다르므로).
- 팀 개설자는 **설정 → 팀 연결 → 팀 해산**에서 모든 팀원의 서버 접근과 참여 코드를 닫을 수 있습니다. 서버의 하위 문서는 보관되며 개인 상담 기록은 각 기기에 남습니다.
- 팀을 나가면 그 팀의 기록만 지우고 다른 팀은 그대로입니다. 예전(팀 하나) 저장 내용은 처음 실행할 때 자동으로 옮겨집니다.

**협업 기능 (4단계)** — 대화창의 **협업** 탭
- **프로젝트 AI 업무 배분** — 프로젝트를 선택하고 Markdown(`.md`)이나 텍스트(`.txt`) 기획서를 넣은 뒤 Claude 또는 GPT로 계산합니다. 팀원이 적은 자기소개·역량·가용 시간과 기존 업무를 바탕으로 담당자, 예상 시간, 배정 이유를 검토하고 선택한 제안을 업무 목록에 반영합니다. 팀원은 기존 방식대로 배정을 수락하거나 이의를 제기할 수 있습니다.
  파일명 아래의 **팀 프로젝트에 저장됨**은 팀원도 같은 기획서를 열 수 있다는 뜻입니다. 이전 서버 규칙에서는 **이 기기에 저장됨**으로 표시되고, 그 기기에서 계산해 반영한 업무는 팀 전체에 공유됩니다.
- **삭제** — 본인의 자기소개와 기획서, 프로젝트 작업·자료 링크를 각 항목에서 삭제할 수 있습니다. 프로젝트 작성자나 팀 관리자는 프로젝트 전체를 삭제할 수 있습니다. 프로젝트 전체 삭제는 포함된 작업·기획서·링크에 적용되며 Drive 원본 파일은 유지됩니다. 서버에서 삭제하려면 해당 버전의 `firestore.rules`를 게시해야 합니다.
- **자기소개**: 할 수 있는 일, 역량(배우는 중/할 수 있음/능숙), 배우고 싶은 일, 주간 가능 시간. 본인만 고칠 수 있고 팀원 모두 봅니다.
- **프로젝트**: 목표, 결과물, 마감일.
- **작업**: 예상 시간, 난이도, 필요한 역량, 먼저 끝나야 하는 작업, 완료 기준, 준비물·참고자료 체크리스트.
- **배분 제안**: 같은 개수가 아니라 다음을 함께 봅니다.
  - 가능 시간 대비 부담 (검토·수정 몫 20%를 먼저 남김)
  - 역량과 배우고 싶은 일 (익숙하지 않으면 시간을 더 잡음)
  - 어려운 일·쉬운 일이 한 사람에게 쏠리지 않는지
  - 선행 작업 순서와 한 사람이 동시에 두 일을 못 한다는 점을 반영한 완료 예상일
  - 작업마다 **배정 이유**와 "자기소개 기반 추정"이라는 불확실성 표시
  - 시간이 모자라거나 마감을 넘으면 몇 시간·며칠이 부족한지와 함께 범위·마감·담당 중 무엇을 바꿔야 하는지 알려 줍니다.
- **수락·이의 제기**: 배정은 제안일 뿐이고, 맡은 사람 본인만 수락할 수 있습니다 (보안 규칙으로도 막음). 이의를 제기하면 배정이 풀리고 다음 제안에서 그 사람은 그 작업에서 빠집니다.
- **고양이의 진행 확인** (말풍선, 조용한 모드·집중 모드를 따름):
  - 배정 확인 → "맡을게요 / 이의 있어요"
  - 시작할 수 있는 일 → "이번 주에는 6시간을 쓸 수 있다고 했죠. 이 작업은 4시간 정도로 예상해요. 나머지는 검토와 수정에 남겨 둘까요?"
  - 앞 작업을 기다리는 중 → 그동안 준비물이나 다른 작업을 권함
  - 준비물이 남았을 때, 마감이 이틀 안으로 다가왔을 때
  - 예상보다 오래 걸릴 때는 꾸짖지 않고 이유를 묻습니다 → "막혔어요 / 잘 되고 있어요 / 끝났어요"
  - 누군가 "막혔어요"를 누르면 다른 팀원 고양이가 도움을 권합니다.
  - 계획대로면 마감이 빠듯할 때 범위·일정·담당 조정을 제안합니다.

**외부 연결 (5단계)** — 설정 → 외부 연결
- **Telegram 알림**: 팀 봇 하나에 각자 `/start` 코드로 연결합니다.
  - 받는 알림: 배정 제안, 막힘 도움 요청, 팀 약속 제안, 자리를 비웠을 때의 내 진행 확인
  - 개인 대화·정리 카드·받은 조언 주제는 보낼 수 있는 알림 종류 자체에 없습니다.
- **Google 캘린더**: 바쁜 시간(free/busy)만 읽어 빈 시간을 계산하고, 내 작업 시간을 첫 빈 틈에 일정으로 잡습니다. 일정 제목·내용은 읽을 권한을 요청하지 않습니다.
- **Google 할 일**: 내가 수락한 작업을 프로젝트별 목록에 올리고, 완료 상태를 양쪽으로 맞춥니다. 제목은 사이 기준이고, Google에서 지운 할 일은 다시 만들지 않습니다.
- 각 연결의 상태, 마지막 결과, 오류를 설정 화면에 그대로 보여 줍니다.

**AI (선택)**
- 설정에서 Claude API 키를 넣으면 사이의 말이 대화 맥락에 맞게 다듬어지고, 정리 카드가 보강됩니다. 키는 Windows 보안 저장소(DPAPI, 내 계정으로만 풀 수 있음)로 암호화해 저장합니다.
- 같은 화면에서 개인 OpenAI API 키와 GPT 모델을 설정할 수 있습니다. 프로젝트 업무 배분, 상담 공유 문안, 팀 약속 작성 화면에서 사용할 제공자를 고릅니다. Claude 팀 공유 키는 해당 팀에서 사용할 수 있습니다.
- 규칙 기반 개인 상담, 기존 팀 기록 열람과 동기화는 API 키 없이도 사용할 수 있습니다. AI로 대화하거나 문안을 만들 때는 해당 기능의 입력이 선택한 제공자(Anthropic 또는 OpenAI)에게 전송됩니다.

  src/
    behavior.rs         고양이 행동 상태 기계
    advice.rs           조언 모음(출처 구분), 말 걸 때·고를 말·조용한 시간
    topics.rs           일반 주제, 행동 요청, 확인할 점, 민감 단서
    language.rs         욕설·평가 감지, 감정 감지, 행동 표현으로 바꾸기
    safety.rs           위험 신호 감지와 안내
    counseling.rs       상담 대화 흐름과 정리 카드

    chat.rs             대화 세션 (이 기기에만 저장)

    team/               Firebase 익명 로그인 + Firestore REST, 시험용 저장소, 여러 팀·지연 전송·팀 약속
    collab/             배분 제안·배정 이유·마감 점검, 진행 확인, 자기소개·프로젝트·작업
    notify.rs           Telegram 봇·채팅 연결·업무 알림
    google/             데스크톱 OAuth(PKCE·루프백), 캘린더 바쁜 시간, 할 일 동기화
    schedule/           한국어 날짜·시간 읽기, 시간 블록 배치, 시간표 수정·캘린더 반영, 말로 고치기
  tests/firebase_real.rs  실제 Firebase 점검
src-tauri/            앱: 고양이 창(클릭 통과·이동), 대화창, 트레이 메뉴, 말풍선 조언, 화면 연결, 업데이트, 시작 프로그램

개발용: `SAI_DEMO=team|chat|cat` 으로 실행하면 정해진 동작을 차례로 실행합니다 (화면 확인용). `SAI_TEAM_FILE=파일` 을 주면 서버 대신 그 파일을 팀 저장소로 써서 한 컴퓨터에서 팀처럼 시험할 수 있습니다.

## 알려진 한계

- 팀 연결은 배포할 때마다 GitHub Actions 에서 실제 Firebase 프로젝트 `saigajoa`로 동작과 권한 규칙을 점검합니다 (`npm run check:firebase`). Windows 실기기에서 고양이 창의 투명 부분 클릭 통과는 아직 따로 확인하지 않았습니다.
- 오래된 주제 문서는 자동으로 지우지 않습니다.
- Google 캘린더·할 일 연동은 실제 계정으로 동작을 확인했습니다 (2026-11-14). Telegram 알림은 가짜 서버로만 검사했고, 실제 봇으로는 아직 확인하지 않았습니다.
- 배분 제안의 가중치(역량·부담·쏠림)는 합리적인 출발점으로 정한 값이고, 실제 팀에서 써 보며 조정이 필요합니다.
- 주간 가능 시간은 한 프로젝트 기준입니다. 여러 프로젝트를 동시에 하면 각 프로젝트에 쓸 시간을 따로 적어야 합니다.
- 새 개인 조언의 발신 계정은 작성자 확인과 철회를 위해 서버에 기록됩니다. 수신 화면에는 발신자의 이름이 표시되지 않습니다.
