# PC 연결 실험 실행과 확인

자동 호스트 설계의 단계 0을 위한 진단 기능이다. 별도 연결 프로그램이나 외부 조정 서비스를 사용하지 않고, 사이 앱 안에서 LAN 발견과 양쪽 장치 인증을 확인한다. 현재 팀 서버 선택·팀 기록·관리자 권한과 분리되어 있으며, 실제 팀 톡의 분산 전환은 다음 단계다.

## 1. 앱에서 실행

### 별도 진단 실행 파일

두 PC에서 검증할 때는 `Sai-Connection-Test-win-x64.zip`의 압축을 풀고 `Sai-Connection-Test.exe`를 각각 실행할 수 있다. 사이의 일반 설치나 로그인은 필요하지 않으며, Windows의 WebView2 실행 환경을 사용한다. 이 진단 창은 일반 앱의 팀 저장소·계정·고양이·자동 시작·업데이트를 초기화하지 않는다. 창을 닫으면 실행도 끝난다.

ZIP에는 공개 실행 파일, SHA-256 해시, 빠른 안내, 아래 상세 안내와 작성용 검증 기록을 넣는다. 개인키나 실제 PC의 연결 카드를 배포 파일에 포함하지 않는다. x64 진단 빌드이며 ARM64 네이티브 설치 검증과 구분한다.

소스에서 같은 ZIP을 만들려면 Windows에서 다음을 실행한다. 일반 앱 빌드에서는 진단 전용 바이너리를 만들지 않도록 `connection-test` 기능으로 분리했다.

```powershell
powershell -NoProfile -File scripts/build-connection-test.ps1
```

결과는 `target/connection-test-win-x64/`와 `target/Sai-Connection-Test-win-x64.zip`에 생성된다. 빌드 스크립트는 화면을 먼저 만들고 Tauri의 정적 리소스를 실행 파일에 포함한다. 진단용 빌드 프로필은 일반 배포 프로필과 구분한다.

### 두 PC의 연결 확인

이 변경을 포함해 빌드한 사이 앱을 같은 LAN의 두 PC에서 실행한다.

1. 양쪽에서 **설정 → PC 연결 실험 → 같은 네트워크의 PC 연결 확인**을 연다.
2. 같은 네트워크에 연결된 LAN을 고른다. `Wi-Fi · 주소`처럼 연결 이름과 주소를 함께 표시하며, 처음에는 아무 주소도 선택하지 않는다. WSL·가상 머신 항목이 함께 보이면 실제 Wi-Fi 또는 유선 LAN을 선택한다.
3. 선택한 LAN에서 15분간 실험을 여는 동의 항목을 체크하고 **실험 시작**을 누른다.
4. A의 공개 연결 정보를 B에, B의 공개 연결 정보를 A에 전달한다. 직접 상대 화면을 보거나 신뢰하는 전달 경로를 이용한다. 각 카드의 공개 인증서 SHA-256 지문을 상대 화면과 대조한다.
5. 양쪽 모두 상대 정보를 붙여 넣고 **상대 정보 등록**을 누른다. 등록은 연결 정보에 담긴 장치를 신뢰한다는 의미다. LAN에서 발견된 장치는 자동 등록되지 않는다.
6. 양쪽에서 **연결 확인**을 누른다. 각 PC에서 마지막 확인 성공 시각이 표시되는지 확인한다.
7. 한쪽에서 **실험 중지**를 누른 뒤 다른 쪽에서 다시 확인한다. 이번 확인은 실패로 표시되어야 한다. 과거 성공 시각은 현재 연결 유지의 보장이 아니다.
8. 중지한 PC에서 다시 시작하면 연결 정보와 지문이 바뀐다. 이전 등록으로 연결되지 않는지 확인한 뒤 양쪽에서 새 정보를 교환한다.

Windows가 앱 통신 허용을 요청할 수 있다. 앱은 방화벽 전체 해제·공유기 포트 개방·관리자 서비스 등록을 수행하지 않는다. 같은 Wi-Fi여도 게스트 격리나 회사 정책으로 기기 간 통신이 막힐 수 있다.

## 2. 이번 실험이 제공하는 범위

| 항목 | 동작 |
|---|---|
| 시작 | 사용자가 선택한 로컬 사설 IPv4 주소의 임시 포트에서만 수신. 앱 시작만으로 열리지 않음 |
| 자동 발견 | 선택한 인터페이스의 mDNS로 실험 세션 ID·공개 지문·주소를 광고. 팀 이름·대화·참여 코드 없음 |
| 등록 | 공개 연결 카드를 사용자가 양쪽에 직접 등록. 실험당 최대 8대 |
| 인증 | TLS 1.3의 양쪽 인증서 검증·개인키 소유 증명, 등록한 인증서와 정확히 일치하는지도 확인 |
| 통신 | 임의 난수를 포함한 크기가 제한된 확인 신호와 응답만 지원. 파일·명령·팀 데이터 API 없음 |
| 수명 | 15분 후 수신·발견 중지. 재시작하면 새 키·세션 생성 |
| 중지 | 수신 중인 연결과 진행 중인 발신 확인 취소, 수신 포트와 발견 기능 정리 |
| 키 보관 | 임시 개인키는 실행 중 메모리에만 존재. 연결 카드·설정 파일·로그에 저장하지 않음 |
| 독립성 | Firebase 로그인·Google 연결·팀 가입 없이 진단 가능 |

TLS 처리는 rustls와 tokio-rustls, 임시 인증서 생성은 rcgen, LAN 발견은 mdns-sd를 사용한다. 인증서 검증을 생략하는 사용자 정의 TLS 검증기는 사용하지 않는다. [rustls 인증서 검증](https://docs.rs/rustls/0.23.46/rustls/client/struct.WebPkiServerVerifier.html), [tokio-rustls](https://docs.rs/tokio-rustls/0.26.4/tokio_rustls/), [rcgen](https://docs.rs/rcgen/0.14.10/rcgen/), [mdns-sd](https://docs.rs/mdns-sd/0.20.2/mdns_sd/)

이번 카드 등록은 실험 상대 확인용이며, 향후 운영 관리자 서명 기반 회원 승인과 구분한다. 기본 암호화 연결 검증을 수신자별 문안 암호화·장기 키 복구·이벤트 동기화 검증으로 해석하지 않는다.

## 3. 구현과 테스트

- `core/src/team/mesh/probe/`: 임시 신원, 공개 카드, TLS 연결, 제한된 확인 메시지, LAN 발견, 종료 처리.
- `src-tauri/src/mesh.rs`: 진단 IPC와 실행 상태. 이전 실험의 요청이 새 실험을 바꾸지 않도록 세션 ID 확인.
- `ui-app/src/chat/settings/mesh.rs`: 시작·등록·확인·중지 화면. 중지 전의 늦은 응답이 새 상태를 덮어쓰지 않도록 구분.

자동 테스트는 루프백에서 별도 신원과 TCP listener를 가진 두세 인스턴스를 실행한다. 양쪽 등록, 미등록 장치 차단, 인증서 바꿔치기, 다른 세션 사칭, 카드·메시지 크기 제한, 종료와 만료, 중지 시 발신·수신 취소를 확인한다.

```powershell
cargo test --locked -p sai-core --target x86_64-pc-windows-msvc team::mesh::probe -- --test-threads=1
cargo check --locked -p sai-ui --target wasm32-unknown-unknown
```

한 PC의 실제 LAN에서 두 인스턴스가 mDNS로 서로 발견되는지도 별도로 확인할 수 있다. 아래 테스트는 지정 주소에 잠깐 실험 포트를 열고 종료한다. 일반 테스트 실행에서는 제외한다.

```powershell
$env:SAI_MESH_LAN_TEST = '이-PC의-사설-IPv4-주소'
cargo test --locked -p sai-core --target x86_64-pc-windows-msvc team::mesh::probe::tests::two_sessions_discover_each_other_on_the_selected_lan -- --ignored --exact --nocapture
```

## 4. 검증 상태와 다음 단계

2026년 11월 15일, x64 테스트 실행 파일을 이용한 루프백 장치 인증 검증과 한 PC의 실제 Wi-Fi 인터페이스에서 두 인스턴스의 mDNS 발견·양방향 TLS 확인이 통과했다. 이 결과는 실제 두 PC 사이의 방화벽·공유기 통신 검증을 대체하지 않는다.

| 확인 대상 | 상태 |
|---|---|
| 서로 다른 임시 신원의 등록과 TLS 확인 | 자동 테스트 통과 |
| 위조·미등록 장치·큰 메시지 거부 | 자동 테스트 통과 |
| 중지·만료·진행 중 연결 취소 | 자동 테스트 통과 |
| 한 PC의 실제 Wi-Fi에서 두 세션 발견·확인 | 별도 LAN 테스트 통과 |
| 휴대용 x64 진단 실행 파일의 창 열기·주소 조회·창 종료 | 이 PC의 실제 Windows 화면에서 확인 |
| 실제 두 PC의 설치·화면 조작·방화벽 통과 | 확인 필요 |
| Windows ARM64 네이티브 빌드·설치 | 확인 필요. x64 실행 결과와 구분 |
| 두 PC의 절전·복귀·네트워크 변경 | 확인 필요 |
| 외부 네트워크·IPv6·CGNAT | 이번 실험의 지원 범위 밖 |

실제 두 PC 검증은 배포 전 확인 항목이며, 사용자가 지금 테스트를 완료해야 다음 개발을 진행할 수 있는 것은 아니다. [장기 장치 신원과 관리자 승인](mesh-identity.md), [승인 장치 연결과 로컬 원본 로그](mesh-local-log.md)는 로컬 자동 테스트로 진행했다. 이 도구가 성공했다고 기존 팀을 자동 이전하거나 데이터베이스를 동료 PC에 복사하지 않는다. 전체 계획은 [자동 호스트와 PC 간 동기화 설계](automatic-host-design.md)를 따른다.
