# 팀 Claude 1회 실검증과 비공개 복귀 — 2026-11-18

사용자가 **공개 연결·샘플 분석 1회 허용**을 선택했다. [준비 계획](2026-11-18-team-ai-secret-check.md)의 검증 팀 한 개, 합성 문서 136바이트, Sonnet 5.5, 전체·팀 하루 시도 1회, 출력 최대 1,024토큰 범위를 따른다. 자동 재시도나 협업·Calendar 저장은 하지 않는다.

앱에서 실제 Claude 분석을 한 번 실행해 요약·할 일 후보·날짜·원문 근거가 표시되는 것을 확인했다. 팀 저장과 Calendar 등록은 하지 않았다. 검증 종료 후 허용 팀을 0개로 비우고 중계를 비공개로 되돌렸으며 공개 주소의 404 응답을 확인했다.

## 현재까지 확인

- 기존 Worker를 기본 `workers.dev` 주소로 일시 배포했다. 버전 미리보기 주소와 본문 로그는 비활성화했다. 새 요청 형식도 이 배포에 포함됐다.
- 인증 없는 `POST /v1/status`는 실제 원격 서비스에서 `401 / login_required`를 반환했다. 이 확인에 자격 증명을 보내거나 Claude를 호출하지 않았다.
- 배포 후에도 필수 Secret 세 이름이 보존됐음을 조회했다. 값은 읽지 않았다.
- 소유자를 확인한 파일 검증 A 팀 하나만 허용하는 정책을 적용했다. 원래의 빈 정책과 비공개 배포 설정을 로컬에 복귀용으로 준비했다.
- 해당 HTTPS 원점을 포함한 Windows x64 미리보기와 설치 파일을 빌드했다. PE의 x64 종류, 실행 파일 안의 정확한 원점, 산출물 전체 체크섬을 확인했다.
- 앱 재시작 후 Google 재로그인 없이 참여 팀과 기존 합성 파일을 복원했다. Drive에서 읽은 본문은 계획의 파일 이름·136바이트·내용과 일치했다.

개발 PC는 ARM64다. x64 Node로 데스크톱 CLI를 처음 실행했을 때 x64용 선택 의존성이 없어 빌드가 시작되지 않았다. 기존 ARM64 Node와 명시적 x64 Rust 빌드 대상으로 실행해 미리보기·NSIS 빌드를 완료했다. Worker 도구는 앞서 준비한 x64 Node를 계속 사용한다. 패키지 잠금 파일이나 설치된 의존성을 이 문제 때문에 삭제하지 않았다.

## 실제 권한 조회 오류와 수정

사용자가 앱의 첫 연결 동의와 본문 전송 체크를 직접 완료했다. 그러나 기존 중계가 첫 권한 목록 조회에도 빈 `pageToken=`을 보내 Google 권한 확인에서 거부됐다. 분석 버튼은 비활성 상태였으며 이때 Claude를 호출하지 않았다. 우선 빈 허용 목록·비공개 상태로 복귀하고 공개 주소의 404 응답을 확인한 뒤 원인을 점검했다.

읽기 전용 소유자 도구로 동일 계정·폴더에서 실제 Google API를 비교했다. 신원·소유자 확인은 성공했고, 빈 페이지 토큰을 포함한 권한 목록 요청은 403, 그 매개변수를 생략한 요청은 200과 명시적 소유자 항목을 반환했다. 앱 설정은 실행 전후 같은 해시를 유지했다. 토큰이나 Google 오류 본문을 출력하지 않았다.

중계가 첫 페이지에서는 `pageToken`을 생략하고 이전 응답의 토큰이 있을 때만 인코딩해 붙이도록 수정했다. [Google 공식 문서](https://developers.google.com/workspace/drive/api/reference/rest/v3/permissions/list)도 이전 응답의 `nextPageToken`을 이어지는 요청에 사용하도록 정의한다. 권한 조건을 완화하거나 소유자 검사를 건너뛰지 않았다.

Node 모의 검사와 실제 workerd 검사에 빈 토큰 거부·둘째 페이지 권한·공백과 특수문자가 있는 토큰의 인코딩을 검증하는 회귀 검사를 추가했다. Node **42개**(중계 19·배포 점검 6·런타임 7·패키징/Google 빌드 설정 10), Rust 읽기 도구 **2개**가 통과했다. 실제 Google 비교 조회도 성공했다.

## 분석 결과와 복귀

수정한 중계로 승인된 검증 환경을 다시 열고 동일 파일을 준비했다. 앱에 저장된 연결 동의가 재사용돼 재로그인이나 연결 권한 동의를 다시 요구하지 않았고, 실제 팀 권한 확인과 분석 준비가 성공했다. 재개한 동일 본문에 대한 전송 확인을 반영한 뒤 분석 버튼을 **한 번만** 눌렀다. 원격 호출의 결과가 불명확할 때 자동으로 재실행하지 않도록 로컬 실행 기록도 남겼다.

- 요약과 할 일 후보 **1개**가 앱의 결과 화면에 표시됐다.
- 제목은 **샘플 검토 (Review the sample)**, 담당자는 비어 있고 마감일은 **2026-11-20**이었다.
- 근거는 원문에 있는 `Task: Review the sample by 2026-11-20.`이었다.
- 후보 선택과 팀 공유 확인은 꺼져 있었고 팀에 추가 버튼은 비활성 상태였다. 팀 할 일·파일·Calendar 변경은 하지 않았다.

이 결과로 등록된 키와 Sonnet 5.5의 실제 이용, Google 팀 권한 확인, 원격 예산 예약을 거친 앱 분석 흐름을 한 소유자 계정·합성 파일에서 확인했다. 실제 청구액이나 제공자 계정 잔액은 조회하지 않았다. 다른 계정·팀원 권한 철회, 원격 재시작 후 예산 보존과 일반 운영 전체를 확인한 결과는 아니다.

분석 뒤 `TEAM_AI_POLICY`를 `version: 1`, `dailyRequests: 1`, `teams: {}`로 복귀하고 `workers_dev: false`, `preview_urls: false`로 배포했다. CLI의 **No targets deployed**, 외부 요청의 **404**, 필수 Secret 세 이름의 보존을 확인했다. 키 값은 조회하지 않았다. 승인된 분석 1회는 사용 완료 상태이며 추가 분석은 실행하지 않는다. 결과 화면은 검토할 수 있도록 열어 두었지만 현재 중계는 비공개이므로 새 분석은 사용할 수 없다. 일반 팀 상시 사용을 위한 정책·한도·운영 결정과 실계정 팀원 검증은 별도 단계다.

실제 계정·팀 식별자·서비스 원점과 배포 버전·검증 진행 상태는 Git에서 제외된 `target/team-ai-operator/`에 기록했다. 앱 빌드 산출물은 `target/preview-dist/win-x64/`에 있다. 정식 배포·GitHub 게시·다른 팀 활성화는 수행하지 않았다.
