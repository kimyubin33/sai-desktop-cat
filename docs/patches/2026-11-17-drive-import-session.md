# Drive 가져오기와 Google 연결 재사용

기준일: 2026-11-17. 실제 Google 계정의 최종 검증은 별도이며, 아래 구현을 배포 완료로 간주하지 않는다.

## 문제와 결정

사용자는 Google에서 파일을 골랐는데 팀에 나타나지 않았고, 연결된 작업마다 로그인·동의를 반복해야 했다. 기존 구현은 선택한 파일이 이미 팀 폴더 안에 있는지 확인했을 뿐 실제로 가져오지 않았다. 외부 데스크톱 Picker는 매번 별도 동의를 요청했다.

사용자가 **첫 로그인에서 Drive 전체 접근 허용 — 반복 동의 없이 사용**을 명시적으로 승인했다. 이 결정이 이전 패치의 최소 `drive.file` 정책을 대체한다. Calendar·Tasks 권한은 추가하지 않는다. 사용자가 OAuth 콘솔·서버를 설정하게 하지 않는다.

## 구현

- 로그인에 `openid`, `email`, `drive.appdata`, 전체 `drive`를 함께 요청한다. 기존 계정은 **Google 연결 갱신**을 한 번 실행한다. 필요한 범위를 허용하지 않으면 기존 계정 연결은 보존한다.
- 일반 파일 선택·팀 연결은 저장된 로그인과 자동 토큰 갱신을 사용한다. 전체 Drive 연결이 있으면 이전 Picker의 별도 토큰을 사용하지 않는다. 철회·만료·Google 정책에 따른 재로그인까지 없애지는 않는다.
- 앱 안에서 내 Drive 폴더, 공유받은 자료, 이름 검색, 다음 페이지, 최대 10개 선택을 제공한다. 초대받은 팀 연결도 앱 안에서 현재 Google 공유 권한과 사이 팀 표시를 확인한다.
- **사본 추가**는 `files.copy`로 팀 폴더에 실제 사본을 생성한다. 원본을 이동하거나 원본의 공유 권한을 바꾸지 않는다. 사본은 팀 폴더의 공유 권한을 상속한다. 원본의 이후 변경을 사본에 자동 반영하지 않는다.
- 복사 권한·팀 쓰기 권한과 원본 변경 번호를 확인한다. 폴더·바로가기·복사 제한 파일은 거부한다. 이미 대상 폴더 안의 파일은 중복 복사하지 않는다. PC 업로드·받기의 25MB 제한은 유지하고 Drive 내부 사본은 PC를 경유하지 않는다.
- 계정별 로컬 가져오기 대기를 저장한다. 일반 파일은 예약한 저장 ID를 재사용하고, Google 문서는 작업 표시로 결과를 조회한다. Google 문서 복사의 결과가 불확실하면 자동 재전송하지 않고 **결과 확인**을 제공한다. 대기 삭제는 원본·이미 생성된 사본을 삭제하지 않는다.
- 저장 결과의 대상 폴더·작업 표시·형식·크기·제공된 체크섬을 확인한 뒤 완료로 표시한다. Google 문서는 본문을 내려받아 비교하지 않는다. 실패·취소 시 이미 생성된 사본이 있을 수 있으므로 대기에서 결과를 확인한다.
- 계정이 바뀌면 선택창을 닫고 오래된 응답을 무시한다. 대기 작업은 생성 당시 계정·팀에 묶는다. 토큰은 기존 Windows 보호 저장 방식을 유지한다.

## 운영과 검증 경계

자동 검사 **127개**가 통과했다(core 121, Windows 앱 4, UI 2). 원본 보존·실제 사본 생성·읽기/복사 제한·일괄 사전 확인·응답 유실 후 재시작 복구·Google 문서의 불확실한 결과·계정/팀 분리·검색 이스케이프·페이지 토큰·저장된 연결 재사용을 확인했다. 이전 Firebase 실계정 검사 3개는 실행하지 않았다. Wasm과 Windows x64 빌드를 확인했다. 가상 자료 화면에서 앱 내 선택창·선택 개수·폴더 이동 후 선택 유지·가져오기 후 목록 반영·초대 팀 연결을 확인했다. 새 Windows 미리보기를 실행했다.

전체 Drive는 Google의 제한된 권한 범위다. 운영자가 Drive API·동의 화면·데스크톱 클라이언트·테스트 사용자·공개 배포 검증 요건을 확인해야 한다. 코드 수정으로 콘솔 상태가 변경되지는 않는다. 앱은 개인 파일을 AI에 자동 전송하지 않는다.

자동 검사는 모의 Google HTTP 응답만 사용한다. 실제 사용자 파일을 복사하거나 동의 화면을 자동 승인하지 않는다. 실계정에서 기존 연결 갱신 → 다른 폴더의 파일 가져오기 → 팀 폴더의 사본 확인 → 반복 선택과 앱 재시작 시 연결 재사용 → 두 번째 계정의 공유 접근을 확인해야 한다. 이 검증을 완료하기 전에는 두 계정·두 PC 전체 흐름이 검증됐다고 표시하지 않는다.

## 근거

- [데스크톱 Picker](https://developers.google.com/workspace/drive/picker/guides/desktop-mobile-picker): 별도 `drive.file` 및 `prompt=consent` 흐름.
- [Drive 권한 범위](https://developers.google.com/workspace/drive/api/guides/api-specific-auth): 전체 Drive의 접근·검증 범위.
- [파일 생성과 복사](https://developers.google.com/workspace/drive/api/guides/create-file): `canCopy`, 사본, 대상 폴더 공유 권한.
- [업로드와 예약 ID](https://developers.google.com/workspace/drive/api/guides/manage-uploads): 중복 생성 방지와 Google Workspace 문서의 예약 ID 제한.
