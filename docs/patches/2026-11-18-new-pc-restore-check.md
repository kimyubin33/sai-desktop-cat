# 새 PC의 Google 계정 복원 확인 준비

기준일: 2026-11-18. **자동 검사와 새 PC용 설치 패키지는 준비 완료, 실제 다른 PC의 설치·로그인·복원은 사용자 요청으로 보류**했다. 사용자는 이 확인을 나중에 진행하고 현재 검증판의 마무리를 요청했다. 같은 개발 PC의 가상 저장소 검사를 실제 PC 두 대의 검증으로 집계하지 않는다.

사용자 흐름은 **설치 → 기존 PC와 같은 Google 계정 로그인 → 기존 팀·파일·설정·협업 조회**다. 서버 주소·JSON·토큰 파일·연결 카드를 입력하지 않는다. 기존 공용 Claude의 앤드위브 AI 한 팀·하루 10회 설정은 유지하고, 이번 복원 확인에서는 AI 분석이나 Calendar 등록을 실행하지 않는다.

## 전달할 설치 파일

`target/Sai-Preview-New-PC-20261118-win-x64.zip`을 만들었다. 크기는 **3,486,229바이트**, SHA-256은 `2d2ff0c6f512ff5aa9de7782e27aa3652d54cb507bbdc55df497e5ecf8456da3`이다. 같은 이름의 `.zip.sha256` 파일에도 기록했다.

ZIP에는 다음 네 파일만 있다.

| 파일 | 용도 |
|---|---|
| `Sai-Preview-Setup-0.9.14.exe` | Windows x64용 독립 미리보기 설치 |
| `preview-build.json` | 미리보기 이름·식별자·CPU·팀 AI 연결 정보 포함 여부 |
| `새 PC에서 시작하기.txt` | 설치·같은 계정 로그인·복원 확인 안내 |
| `SHA256SUMS.txt` | 위 세 파일의 SHA-256 |

설정 폴더·Google 로그인 토큰·개인 AI 키·대화·로그·운영 정책은 ZIP에 넣지 않았다. 개인 자료를 옮겨 복원된 것처럼 보이게 하지 않는다. Google 로그인용 앱 연결 정보와 공용 AI의 공개 연결 원점은 기존 설치 실행 파일에 포함돼 있다. 공용 Claude API 키는 서비스 Secret에 유지한다.

직전 실계정 검증에 사용한 설치 파일을 재사용했다. 앱 소스를 바꾸거나 버전을 올리지 않았고 새 설치 파일 빌드를 했다고 표시하지 않는다. 기존 배포 폴더의 두 실행 파일 SHA-256, 포터블 앱의 x64 PE 헤더와 기존 중계 원점 포함 여부를 확인했다. 설치 파일은 `NotSigned`인 정식 배포 전 검증판이다. 설치·Google 로그인과 동의는 사용자가 해당 PC에서 직접 진행한다.

새 PC에는 Setup 설치를 기준으로 안내한다. 설치 설정은 현재 사용자·별도 앱 ID·별도 시작 메뉴이며, WebView2가 없을 때 부트스트랩을 내려받으므로 인터넷 연결이 필요하다. 실제 새 PC의 WebView2 설치 성공 여부는 아직 확인하지 않았다.

## 로컬에서 확인한 것

기존 자동 검사 **25개**가 통과했다. 실제 계정·Drive 파일·유료 AI를 사용하는 검사는 아니다.

- 프로필 검사 **11개**: 새 기기의 기본값 미전송, 복원 실패 시 기존 원격 상태 보존, 계정 분리·로그아웃 도중 응답 차단, 두 저장소의 변경·탈퇴 기록 병합과 재시도.
- Google 전체 흐름 검사 **4개**: 분리한 두 PC 저장소의 팀·설정·파일·협업 복원, 재시작 후 로그인 재사용, 복원 실패 시 팀 작업 차단, 계정 전환 후 이전 자료 숨김. AI·Calendar는 모의 서버다.
- 설치 패키지·Google 앱 연결 형식 검사 **10개**: CPU·PE·체크섬·누락·파일 선별, 미리보기 설치 파일 비교와 잘못된 OAuth 앱 형식 거부.

실행한 Rust 필터는 `google::profile::tests`와 `google::files::tests::workspace_workflow`다. 전체 흐름 소스 파일 이름은 `workspace_tests.rs`지만 실제 테스트 모듈 이름은 `workspace_workflow`다. 이름이 맞지 않아 0개가 실행된 결과를 통과 수로 세지 않았다.

ZIP을 다시 열어 정확한 파일 목록·각 항목 크기·SHA-256을 준비 폴더와 대조했다. 설치 실행 파일은 기존 검증 파일과 동일하다. 이번 실서비스 분석·Drive 변경·협업 저장·Calendar 등록은 각각 0회다. 패키지를 GitHub나 공개 주소에 발행하지 않았다.

## 다른 PC에서 확인할 것

1. ZIP을 다른 Windows PC에 복사해 압축을 풀고 Setup으로 설치한다.
2. 사이 미리보기에서 기존 PC와 같은 Google 계정으로 로그인한다. 기존 PC의 토큰·설정 폴더를 복사하지 않는다.
3. 파일에서 기존 **앤드위브 AI** 팀과 기존 파일이 보이는지 확인한다.
4. 설정의 내 이름·고양이 이름·말 거는 빈도를 기존 PC와 비교하고 협업에서 같은 팀의 내용을 확인한다. 업무가 없던 팀의 빈 목록은 정상이다.

먼저 조회와 복원 상태만 확인한다. AI 분석·업무 생성·일정 등록은 이 확인의 통과 조건이 아니다. 팀이 보이지 않거나 오류가 표시되면 해당 문구를 기록하고 복원 실패를 빈 계정으로 확정하지 않는다.

사용자가 실제 다른 PC의 확인을 보류했으므로 지금 결과를 다시 요청하지 않는다. 이후 [검증판 마무리](2026-11-18-preview-checkpoint.md)에서 안내·접근성을 보완해 최신 설치 묶음을 만들었다. 나중에 이 검증을 재개하면 최신 묶음을 사용하고 실제 PC 종류, 같은 계정 여부, 설치·팀·설정·파일·협업별 결과와 실패 범위를 추가한다. 로그인 완료 보고만으로 파일·설정까지 모두 복원됐다고 표시하지 않는다.

준비 결과는 Git에서 제외한 `target/new-pc-artifact-audit.json`, `target/new-pc-restore-readiness.json`에 보관한다. 소유자·팀원 권한, 실제 팀원 AI 분석, 다른 CPU·네트워크·설치 실패 경로와 정식 배포 완료는 이 준비 결과로 대신하지 않는다.
