# 사이 — 고양이 협업 도우미

각 팀원의 바탕화면을 돌아다니는 고양이 **사이**가 평소에는 짧은 조언을 건네고, 팀원 때문에 속상한 이야기를 들어 주며 감정·사실·추측을 나눠 정리하는 데스크톱 앱입니다. 정리된 고민은 원문 없이 **일반 주제**로만 바뀌어 상대의 고양이가 평소 조언 속에 자연스럽게 섞어 말하고, 팀의 업무 분배와 진행 확인까지 함께 챙깁니다.

개발 방향은 [docs/development-direction.md](docs/development-direction.md)를 따릅니다. 이 저장소는 그 문서의 **1~5단계**(경험 시제품, 개인 대화, 소규모 팀 연결, 협업 기능, 외부 연결)를 구현한 상태입니다. 팀 연결은 Firebase를 쓰며 설정 방법은 [docs/firebase-setup.md](docs/firebase-setup.md), Telegram·Google 연결은 [docs/integrations-setup.md](docs/integrations-setup.md)에 있습니다.

## 기술 구성

**Tauri 2 + Rust**로 만듭니다. 팀 동기화·상담 흐름·배분·시간표·Google·Telegram·AI·저장·업데이트 같은 로직은 모두 Rust(`core/`, `src-tauri/`)이고, 화면(`ui/`)만 HTML·CSS와 화면을 그리는 짧은 JS입니다. 설치 파일이 작고(수 MB) 메모리를 적게 씁니다. Windows 10·11에 기본으로 들어 있는 WebView2로 화면을 그립니다.

## 실행

Rust(rustup, `rustup target add wasm32-unknown-unknown`)와 Node.js(Tauri 빌드 도구용)가 필요합니다. 코드는 모두 Rust 이고, 화면도 Rust 로 써서 WebAssembly 로 만듭니다 (`cargo run -p xtask -- ui`, 빌드할 때 자동 실행).

```bash
npm install          # Tauri 빌드 도구 설치
npm run dev          # 개발 실행
npm test             # 핵심 로직 테스트 (cargo test --workspace)
npm run check:firebase  # 실제 Firebase 에서 팀 기능·권한 규칙 점검 (인터넷 필요)
npm run build        # 설치 파일 만들기 (Windows 에서)
```

### 팀원에게 나눠 주기 · 새 버전 배포 (자동 업데이트)

- 팀원은 [Releases](https://github.com/kimyubin33/sai-desktop-cat/releases/latest)의 `Sai-Setup-x.y.z.exe`를 한 번 설치하면 됩니다. 스냅드래곤 같은 ARM 노트북(Windows on ARM)은 `Sai-Setup-x.y.z-arm64.exe`를 받으면 에뮬레이션 없이 더 빠르게 돌아갑니다. 설치 없이 쓰려면 `Sai-Portable-x.y.z.exe` 하나만 실행해도 됩니다.
- 설치된 사이는 켤 때와 3시간마다 새 버전을 확인합니다. 새 버전이 있으면 받아서 `SHA256SUMS.txt`로 확인해 두고, 고양이가 "지금 적용"할지 묻습니다. "나중에"를 고르면 프로그램을 끌 때 적용됩니다.
- 포터블로 쓰던 사람이 업데이트를 적용하면 설치 화면이 떠서 설치 버전으로 바뀝니다.
- 0.7.x 이하(Electron 버전)를 쓰던 사람은 새 설치 파일을 한 번 설치하고, 예전 사이는 "앱 및 기능"에서 지워 주세요. 팀·프로젝트·작업은 서버에 있어서 그대로이고, 이 컴퓨터의 설정·로그인은 다시 해야 합니다.

새 버전을 배포하는 방법:

1. `Cargo.toml`의 `[workspace.package]` `version`을 올립니다 (예: 0.8.0 → 0.8.1).
2. 커밋해서 `main`에 push 합니다.

그러면 GitHub Actions가 Windows에서 테스트와 실제 Firebase 점검을 한 뒤 설치 파일을 만들어 Releases에 올립니다. 이미 배포된 버전이면 아무것도 하지 않습니다.
Google 연결 정보가 설치 파일에 들어가도록 저장소 **Settings → Secrets and variables → Actions**에 `GOOGLE_CLIENT_JSON` 시크릿을 넣어 두세요 (형식은 `config/README.md`).

Windows를 우선 대상으로 만들었고, macOS·Linux에서도 실행됩니다 (Linux는 투명 부분 클릭 통과가 제한될 수 있음).

## 지금 할 수 있는 것

**바탕화면 고양이 (1단계)**
- 작업 표시줄 위를 걷고, 앉고, 식빵 자세로 쉬고, 잠듭니다. 도트 그림은 코드로 그려서 외부 이미지가 없습니다.
- 회색 줄무늬 고양이를 천천히 끌어 놓으면 바닥으로 내려와 앉습니다. 다른 모니터로도 옮길 수 있습니다.
- 잡은 채로 빠르게 여러 번 흔들면 “어지러...”라고 합니다. 화면 가장자리로 세게 던져 부딪히면 “아야!” 하고 튕깁니다.
- 다른 팀원이 보낸 새 톡은 화면 오른쪽 위에서 얼굴을 내민 고양이가 보여 줍니다. 말풍선을 누르면 해당 팀의 톡이 열립니다.
- 고양이를 클릭하면 대화창, 오른쪽 클릭하면 메뉴가 열립니다. 투명한 부분은 클릭이 아래 창으로 통과합니다.
- 평소에 일상 한마디·생각거리·협업 조언·고전 문장을 말풍선으로 건넵니다.
  - 사이가 직접 쓴 문장은 `사이의 한마디`로, 고전·속담은 출전(예: 『논어』 위정편)으로 표시합니다. 출처가 불확실한 "유명인 명언"은 넣지 않았습니다.
- 말풍선마다 **닫기 · 나중에 · 이런 말 줄이기 · 이야기하기**가 있고, 최근 한 말은 반복하지 않습니다.
- 트레이·오른쪽 클릭 메뉴: 조언 한마디 듣기, 조용한 모드, 집중 모드(30분/1시간/2시간), 말 거는 빈도, 숨기기.
- 설정: 방해 금지 시간(자정 넘김 지원), "이런 말 줄이기" 기록 초기화.

**개인 대화 (2단계)**
- 대화 시작 시 고르기: 팀원 일로 속상해요 / 내 사정을 이야기하고 싶어요 / 그냥 이야기할래요.
- 속상한 이야기는 `감정 알아주기 → 어떤 약속·기대였는지 → 서로 확인한 약속이었는지·상대 사정 → 실제 영향 → 바라는 것` 순서로 묻고 **정리 카드**를 만듭니다. "정리해 줘"라고 하거나 버튼으로 언제든 정리할 수 있고, 질문은 건너뛸 수 있습니다.
- 정리 카드: 내가 보고한 사건, 약속 확인 여부(추측은 추측으로 표시), 공동 기록 확인 여부, 감정, 영향, 필요, 가능한 행동 요청, **사람에 대한 평가를 행동으로 바꾼 표현**, 아직 확인할 점, 반영할 일반 주제. 직접 고칠 수 있습니다.
- 욕설·평가 표현은 정리 카드에 옮기지 않습니다.
- "죽고 싶다"처럼 긴급한 위험 신호가 보이면 흐름을 멈추고 안전 확인과 상담 전화(109, 1577-0199, 112·119)를 먼저 안내하며, 그 대화는 공유할 수 없게 막습니다. "힘들어 죽겠다" 같은 일상 표현은 위험 신호로 보지 않습니다.

**공유 범위와 개인정보**
- 주제마다 `비공개로 두기 / 검토 후 공유 / 허용한 주제로 자동 반영`과 `관련 팀원의 고양이에게 / 팀 공통 약속으로 제안`을 고릅니다. 상대의 고양이가 할 말과 팀 제안 문안을 미리 보여 줍니다.
- 공유 대기함(`shared/outbox.json`)에는 **주제, 미리 써 둔 일반 문안, 공유 범위, 대략적인 주(週)** 만 저장됩니다. 원문·이름·날짜·사건은 들어갈 자리가 없고, 저장 직전에 원문 조각이 섞였는지 한 번 더 검사합니다.
- 건강·가족·연애·돈·성적처럼 민감할 수 있는 내용이 보이면 자동 반영을 막고 검토 후 공유로만 둘 수 있습니다.
- 같은 사람이 같은 주제를 여러 번 공유해도 한 건으로 유지합니다 (여러 명의 의견처럼 부풀리지 않음).
- 대화 원문(`private/conversations.json`)은 이 컴퓨터에만 남고, 보관 기간(7/30/90일 또는 직접 삭제)이 지나면 지워집니다.
- 화면 감시, 키 입력 수집, 메신저 열람은 하지 않습니다.

**팀 연결 (3단계, Firebase)**
- 한 명이 팀을 만들고 6자리 참여 코드로 팀원이 들어옵니다. 계정은 익명 로그인이고, 로그인 정보는 각자 컴퓨터에 암호화해 둡니다.
- 공유할 때 주제마다 받을 팀원을 고릅니다. 서버에는 주제 id·받는 사람·주(週)만 가고, **보낸 사람 정보와 문안은 올라가지 않습니다.** 받는 쪽 앱이 자기 일반 문안으로 말합니다.
- 자동 반영은 몇십 분~세 시간 늦춰 보내 보낸 시각으로 짐작하기 어렵게 합니다. 검토 후 공유는 정리함에서 확인해야 보냅니다.
- 받는 쪽 고양이는 최근 3주 동안 받은 주제를 평소 조언에서 더 자주 다루고, 말풍선에는 받은 것인지 드러나지 않습니다.
- **내 사정도 있어요**: 팀에 연결되면 모든 협업 조언 말풍선에 붙습니다. 누르면 그 주제로 내 사정 이야기를 하고, 정리 뒤 그 주제 조언을 멈추거나 팀 약속으로 제안할 수 있습니다. 보낸 쪽 정리함에는 "상대가 사정을 이야기함"으로 표시되고 팀 약속 제안을 권합니다.
- **팀 약속**: 제안자는 보이지 않고, 같은 주의 같은 주제 제안은 하나로 모입니다. 고양이가 말풍선으로 동의를 묻고, 모두 동의하면 팀 약속이 됩니다.
- 설정에 팀 이름, 참여 코드, 팀원, 마지막 동기화 시각, 연결 오류를 그대로 보여 줍니다.
- 보안 규칙(`firestore.rules`): 팀원만 팀 데이터 접근, 받은 주제는 받는 사람만 목록 조회, 보류는 받는 사람만, 팀 약속 응답은 각자 자기 것만.
- Firebase 없이 한 컴퓨터에서 시험하는 **로컬 시험 모드**도 있습니다 (docs/firebase-setup.md 5절).

**여러 팀 (팀플이 여러 개일 때)**
- 설정 → 팀 연결에서 팀을 더 만들거나 참여 코드로 계속 추가할 수 있습니다. 팀마다 내 이름도 따로 정합니다.
- 대화창 위쪽 이름 아래의 팀 고르기로 **보고 있는 팀**을 바꿉니다. 협업 탭·정리함·공유 기본값이 그 팀을 따릅니다.
- 고민을 공유할 때 **어느 팀 이야기인지** 고르면, 받을 팀원 목록도 그 팀으로 바뀝니다. 주제는 그 팀에만 갑니다.
- 고양이 말풍선(받은 조언 주제, 팀 약속 제안, 진행 확인)은 **모든 팀을 함께** 봅니다. 팀이 둘 이상이면 출처 줄에 팀 이름이 붙습니다.
- 자기소개·가능 시간은 팀마다 따로입니다 (팀플마다 쓸 수 있는 시간이 다르므로).
- 팀을 나가면 그 팀의 기록만 지우고 다른 팀은 그대로입니다. 예전(팀 하나) 저장 내용은 처음 실행할 때 자동으로 옮겨집니다.

**협업 기능 (4단계)** — 대화창의 **협업** 탭
- **프로젝트 AI 업무 배분** — 프로젝트를 선택하고 Markdown(`.md`)이나 텍스트(`.txt`) 기획서를 넣은 뒤 Claude 또는 GPT로 계산합니다. 팀원이 적은 자기소개·역량·가용 시간과 기존 업무를 바탕으로 담당자, 예상 시간, 배정 이유를 검토하고 선택한 제안을 업무 목록에 반영합니다. 팀원은 기존 방식대로 배정을 수락하거나 이의를 제기할 수 있습니다.
  파일명 아래의 **팀 프로젝트에 저장됨**은 팀원도 같은 기획서를 열 수 있다는 뜻입니다. 이전 서버 규칙에서는 **이 기기에 저장됨**으로 표시되고, 그 기기에서 계산해 반영한 업무는 팀 전체에 공유됩니다.
- **자기소개**: 할 수 있는 일, 역량(배우는 중/할 수 있음/능숙), 배우고 싶은 일, 주간 가능 시간. 본인만 고칠 수 있고 팀원 모두 봅니다.
- **프로젝트**: 목표, 결과물, 마감일.
- **작업**: 예상 시간, 난이도, 필요한 역량, 먼저 끝나야 하는 작업, 완료 기준, 준비물·참고자료 체크리스트.
- **배분 제안**: 같은 개수가 아니라 다음을 함께 봅니다.
  - 가능 시간 대비 부담 (검토·수정 몫 20%를 먼저 남김)
  - 역량과 배우고 싶은 일 (익숙하지 않으면 시간을 더 잡음)
  - 어려운 일·쉬운 일이 한 사람에게 쏠리지 않는지
  - 선행 작업 순서와 한 사람이 동시에 두 일을 못 한다는 점을 반영한 완료 예상일
  - 작업마다 **배정 이유**와 "자기소개 기반 추정"이라는 불확실성 표시
  - 시간이 모자라거나 마감을 넘으면 몇 시간·며칠이 부족한지와 함께 범위·마감·담당 중 무엇을 바꿔야 하는지 알려 줍니다.
- **수락·이의 제기**: 배정은 제안일 뿐이고, 맡은 사람 본인만 수락할 수 있습니다 (보안 규칙으로도 막음). 이의를 제기하면 배정이 풀리고 다음 제안에서 그 사람은 그 작업에서 빠집니다.
- **고양이의 진행 확인** (말풍선, 조용한 모드·집중 모드를 따름):
  - 배정 확인 → "맡을게요 / 이의 있어요"
  - 시작할 수 있는 일 → "이번 주에는 6시간을 쓸 수 있다고 했죠. 이 작업은 4시간 정도로 예상해요. 나머지는 검토와 수정에 남겨 둘까요?"
  - 앞 작업을 기다리는 중 → 그동안 준비물이나 다른 작업을 권함
  - 준비물이 남았을 때, 마감이 이틀 안으로 다가왔을 때
  - 예상보다 오래 걸릴 때는 꾸짖지 않고 이유를 묻습니다 → "막혔어요 / 잘 되고 있어요 / 끝났어요"
  - 누군가 "막혔어요"를 누르면 다른 팀원 고양이가 도움을 권합니다.
  - 계획대로면 마감이 빠듯할 때 범위·일정·담당 조정을 제안합니다.

**외부 연결 (5단계)** — 설정 → 외부 연결
- **Telegram 알림**: 팀 봇 하나에 각자 `/start` 코드로 연결합니다.
  - 받는 알림: 배정 제안, 막힘 도움 요청, 팀 약속 제안, 자리를 비웠을 때의 내 진행 확인
  - 개인 대화·정리 카드·받은 조언 주제는 보낼 수 있는 알림 종류 자체에 없습니다.
- **Google 캘린더**: 바쁜 시간(free/busy)만 읽어 빈 시간을 계산하고, 내 작업 시간을 첫 빈 틈에 일정으로 잡습니다. 일정 제목·내용은 읽을 권한을 요청하지 않습니다.
- **Google 할 일**: 내가 수락한 작업을 프로젝트별 목록에 올리고, 완료 상태를 양쪽으로 맞춥니다. 제목은 사이 기준이고, Google에서 지운 할 일은 다시 만들지 않습니다.
- 각 연결의 상태, 마지막 결과, 오류를 설정 화면에 그대로 보여 줍니다.

**AI (선택)**
- 설정에서 Claude API 키를 넣으면 사이의 말이 대화 맥락에 맞게 다듬어지고, 정리 카드가 보강됩니다. 키는 Windows 보안 저장소(DPAPI, 내 계정으로만 풀 수 있음)로 암호화해 저장합니다.
- 프로젝트 배분에 GPT를 쓰려면 같은 설정 화면에 개인 OpenAI API 키를 입력합니다. 사용할 제공자는 프로젝트의 AI 계산 화면에서 선택합니다.
- 키가 없거나 호출이 실패해도 규칙 기반 상담 흐름이 그대로 동작합니다. 대화 단계, 안전 확인, 공유 범위 결정은 항상 앱 규칙이 맡고 AI는 문장과 정리 품질만 돕습니다.
- 키를 쓰면 대화 내용이 Anthropic API로 전송된다는 점을 설정 화면에 표시합니다.

## 알려진 한계

- 팀 연결은 배포할 때마다 GitHub Actions 에서 실제 Firebase 프로젝트 `saigajoa`로 동작과 권한 규칙을 점검합니다 (`npm run check:firebase`). Windows 실기기에서 고양이 창의 투명 부분 클릭 통과는 아직 따로 확인하지 않았습니다.
- 오래된 주제 문서는 자동으로 지우지 않습니다.
- Google 캘린더·할 일 연동은 실제 계정으로 동작을 확인했습니다 (2026-11-14). Telegram 알림은 가짜 서버로만 검사했고, 실제 봇으로는 아직 확인하지 않았습니다.
- 배분 제안의 가중치(역량·부담·쏠림)는 합리적인 출발점으로 정한 값이고, 실제 팀에서 써 보며 조정이 필요합니다.
- 주간 가능 시간은 한 프로젝트 기준입니다. 여러 프로젝트를 동시에 하면 각 프로젝트에 쓸 시간을 따로 적어야 합니다.
- 받는 사람을 고르는 것 자체가 "누구에 대한 고민인지"를 보낸 사람 쪽에서 정하는 일이라, 받는 사람은 팀 안의 누군가가 자신에 관해 공유했다는 것까지는 알 수 있습니다 (누구인지는 서버에도 남지 않음).
