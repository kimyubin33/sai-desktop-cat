# 캐릭터 AI와 중재 전달 설계 — 2026-11-18

사이의 핵심 경험은 두 가지다.

1. 바탕화면의 불꽃 캐릭터가 상황에 맞춰 **먼저 말을 건다**.
2. 상담 중에 사용자가 팀원에게 전하고 싶은 말이 생기면, 캐릭터가 그 말을 **상처나 화가 덜 나는 부탁으로 바꿔 대신 전한다**.

비용 원칙: 개발·운영 측이 사용자 수만큼 늘어나는 AI 비용을 떠안지 않는다. 메시지를 보관하거나 중계하는 서버도 두지 않는다.

## 역할 분담

| 역할 | 담당 | 이유 |
|---|---|---|
| 상담 대화, 전할 말 판단·다시 쓰기 | Claude API(사용자가 연결한 키) | 판단 품질이 중요하다. 이미 `core/src/ai/delivery.rs`에 구현돼 있다 |
| 위기 감지, 대화 단계 | 규칙(`safety.rs`, `counseling.rs`) | 모델에 맡기지 않는다 |
| 캐릭터가 먼저 거는 말 | **이 PC의 llama.cpp 모델** | 자주, 짧게, 무료로, 내용이 PC 밖으로 나가지 않아야 한다 |
| 받은 메시지를 언제 건넬지 | 규칙 | 예측 가능해야 한다 |
| 전달 수단 | Google Drive 개별 공유 | 서버 없음. 보낸 사람은 실명으로 표시된다(익명 아님) |

## 1단계 — 이 PC에서 도는 캐릭터 AI

- **런타임**: llama.cpp `llama-server`를 처음 켤 때 내려받는다. 빌드 번호와 sha256은 코드에 고정한다. 설치 파일 크기는 늘리지 않는다.
- **모델**: Qwen3-4B-Instruct-2507 Q4_K_M(Apache-2.0, 약 2.5GB). 다운로드는 이어 받기를 지원하고, 끝나면 sha256으로 검증한다.
- **실행**: `127.0.0.1`의 임의 포트에서만 연다. 매번 새로 만든 API 키를 요구하므로 다른 프로그램이 이 서버를 쓸 수 없다. 필요할 때만 켜고, 10분 동안 쓰지 않으면 끈다. 앱이 꺼지면 함께 꺼진다.
- **말 거는 때**: 앞으로 고칠 일을 줄이려고 지금의 규칙을 그대로 쓴다. 말 거는 빈도와 방해 금지 시간을 따른다. 사용자가 15분 이상 자리를 비웠다가 돌아온 때도 말을 건다.
- **모델이 받는 것**: 시간대, 요일, 말을 거는 계기, 기존 조언 문구 하나(주제 씨앗), 최근에 한 말(반복 방지). 상담 원문은 넣지 않는다.
- **결과 검사**: 한 줄인지, 최대 90자인지, 한국어인지 확인한다. 이모지·목록 기호, 링크·연락처, 위험 표현, 욕설이 있으면 버린다. 검사에 실패하거나 모델이 없거나 60초 안에 답하지 않으면, 기존 조언 문구로 대신한다.

### 1단계 구현 상태

| 위치 | 내용 |
|---|---|
| `core/src/local_ai/` | 받기·검증·풀기, 서버 실행·종료, 캐릭터 프롬프트·결과 검사 |
| `src-tauri/src/advisor.rs` | 정해진 때에 말 걸기, 자리 비움 후 돌아왔을 때 말 걸기, 실패하면 기존 문구로 대신하기, 쉬는 서버 끄기 |
| 설정 → 캐릭터 AI | 받기·멈추기(이어 받기)·켜기·한마디 듣기·지우기, 메모리 부족 안내 |

- **테스트로 확인한 것**: 이어 받기, 해시가 다른 파일 거부, 압축 경로 탈출(zip-slip) 거부, 지우기, 세션 키 전달, 결과 문장 검사.
- **실제 모델로 확인한 것(2026-11-19, 16GB ARM64 PC, x64 빌드를 에뮬레이션으로 실행)**: 앱과 같은 코드로 받기·검증·풀기에 약 5분 걸렸다. 서버를 처음 켜서 첫 답을 받기까지 36~39초, 그 뒤 한 번에 10~22초 걸렸다. ARM64 빌드로 실행하면 더 빠를 것으로 예상한다. `cargo test -p sai-core live_model_speaks -- --ignored`(`SAI_LIVE_DIR` 필요)로 다시 돌릴 수 있다.
- **조정한 내용**:
  - 처음 프롬프트에서는 12개 중 4개만 통과했다. 대부분 이모지 때문에 버려졌다.
  - 통과한 말에도 이모티콘, 존댓말, 짐작("야구 보고 있구나?")이 섞였다.
  - 그래서 이모지와 따옴표는 떼고, 한글 외 글자·존댓말·짐작 표현·최근과 비슷한 말은 버리도록 바꿨다. 정확한 시각은 넘기지 않고, 예시를 넣고, temperature를 0.6으로 낮췄다. 검사에 걸리면 한 번 다시 만든다.
  - 조정 후에는 첫 시도에서 12개 중 7개가 통과했다. 버려진 5개는 모두 최근에 한 말과 비슷했다. 앱에서는 이때 한 번 더 시도한다.
- **상담 문구(`care`, 15개)**: 감정을 알아주고 스스로 돌아보게 하는 말을 `core/src/advice.rs`에 추가했다.
  - 상담 문구와 고전 인용은 캐릭터 AI가 바꿔 쓰지 않고 그대로 보여 준다(`verbatim_kind`).
  - 자리를 비웠다가 돌아왔을 때 고른 주제가 상담 문구나 고전 인용이면, 주제 없이 반기는 말만 만든다.
  - 가중치 기준으로 상담 문구는 낮에 약 26%, 저녁(18시 이후)에 약 33% 나온다. 그대로 보여 주는 말 전체는 35~40%다.
- **남은 한계**: 4B 모델이라 어색한 표현("창밖 숨 쉬는 걸 보고 싶어?")이 가끔 나온다. 주제를 이미 한 일처럼 말하기도 한다("팀원한테 고마워했어?"). 품질이 부족하면 더 큰 모델이나 고정 문구 비율 조정을 검토한다.
- **서버 실행 옵션**: 오래 유지된 옵션만 쓴다(`-m --host --port --api-key -c -np -t --no-webui`). 시작에 실패하면 서버 로그의 마지막 줄을 보여 준다.

## 2단계 — 중재 전달(Drive 실명 방식)

흐름(판단·문안은 기존 `ai/delivery.rs`를 쓴다):

1. 상담 중 사용자가 "전해 줘"라고 직접 요청할 때만 시작한다. 자동으로 감지해 보내지 않는다.
2. Claude가 `skip`·`question`·`draft` 중 하나를 고른다. 문안은 관찰 → 영향 → 필요 → 부탁 순서로 쓴다.
3. 규칙 검사를 한다(이미 있음: 원문 유출, 식별자, 욕설, 위험 표현). 대화 원문 없이 문안만 보는 **독립 검토**를 한 번 더 한다(Claude, 400자 이내).
4. 사용자가 "상대에게는 이렇게 보여요" 미리보기를 확인하고 승인한다. 수정할 수 있다.
5. 보내는 사람의 Drive에 메시지 파일을 만들고, 받는 사람 이메일에만 `reader`로 공유한다. 알림 메일은 보내지 않는다. 파일에는 앱 전용 표시를 붙인다.

받는 쪽:

- 공유받은 메시지 파일을 찾는다. 같은 팀 폴더의 멤버가 보낸 것만 받는다.
- **받는 쪽에서 직접 한도를 건다.** 보낸 사람 한 명당 한 주에 2건까지만 받는다. 보내는 쪽 앱을 고쳐도 이 한도는 우회할 수 없다. 특정 사람이나 팀의 메시지를 끌 수 있다.
- 캐릭터가 한가한 때에 건넨다. 이때 **"○○님이 사이에게 부탁한 말이야. 사이가 부드럽게 다듬었어"**라고 출처를 밝힌다. 캐릭터 자신의 의견처럼 꾸미지 않는다.
- 반응: "알겠어 / 이야기해 보고 싶어 / 잘 모르겠어". 받는 사람이 자기 Drive에 반응 파일을 만들어 보낸 사람에게 공유한다.

### 2단계 구현 상태

| 위치 | 내용 |
|---|---|
| `core/src/ai/delivery.rs` | 중재 문안 프롬프트(`mediation_draft`), 독립 검토(`review_mediation`, 형식이 어긋나면 통과시키지 않음), 고친 문안의 기기 검사 |
| `core/src/google/mediation.rs` | 팀원 명단 파일, "사이 메시지" 폴더, 메시지·반응 파일 만들기와 한 사람 공유, 받은 파일 확인 |
| `core/src/mediation.rs` | 받는 쪽 한도(보낸 사람당 주 2건), 보내는 쪽 한도(받는 사람당 주 2건), 끄기, 반응 짝 맞추기, 말풍선 문구 |
| `src-tauri/src/mediation.rs`, `advisor.rs` | 화면 요청 처리. 10분마다 받은 말을 확인하고, 한가한 때 출처를 밝혀 건넨다. 말풍선에서 바로 답할 수 있다 |
| AI 탭 → "팀원에게 전해 줘" | 팀·받는 사람 고르기, 요점 덧붙이기, 다듬기, 미리보기·수정, 확인 후 보내기, 받은 말·보낸 말 목록 |

- **팀원 명단**: 팀 폴더 소유자만 Drive 공유 목록을 볼 수 있다. 그래서 소유자의 앱이 폴더 안에 `sai-roster-v1.json`을 만들고, 팀원을 초대·변경·내보낼 때와 팀원 목록을 열 때 고친다.
  - 받는 쪽은 소유자가 만들고 **마지막으로 고친 사람도 소유자인** 명단만 믿는다. 편집 권한이 있는 팀원이 내용을 바꾸면 그 명단은 무시된다.
  - 명단이 아직 없는 팀에서 온 말은 거부하지 않고 다음 확인 때로 미룬다.
- **보낸 사람 확인**: 파일 내용에 적힌 이름이 아니라 Drive가 알려 주는 파일 소유자로 정한다.
- **테스트로 확인한 것**:
  - 한 사람에게만 알림 없이 보기 권한으로 공유한다. 공유에 실패하면 파일을 지운다.
  - 팀원이 아닌 사람이나 나 자신에게는 보내지 않는다.
  - 내보낸 팀원은 명단에서 빠진다.
  - 위조된 명단과, 편집자가 고친 명단은 믿지 않는다.
  - 명단에 없는 사람의 말, 형식이 틀린 파일, 모르는 팀에서 온 말은 거른다.
  - 받는 쪽 한도와 끄기가 적용된다. 반응은 내가 보낸 말의 받는 사람이 보낸 것만 받는다.
- **아직 확인하지 않은 것**: 실제 Google 계정 두 개로 주고받기, 실제 Claude 문안 품질.
  - 받은 말 목록은 "나와 공유됨" 검색을 써서 Drive 전체 접근 권한이 필요하다. 이 권한이 없으면 확인 화면에서 연결을 갱신하라고 안내한다.

## 3단계 — 안전과 남용 방지

- **위험 신호가 있는 상담**: 괴롭힘, 차별, 자해·타해 신호가 있으면 순화해서 전하지 않는다. 안전 안내와 도움받을 곳을 보여 준다(기존 안전 보류를 넓힌다).
- **팀 범위**: 받는 사람이 현재 팀 멤버가 아니면 보내지 않는다.
- **알려 둘 한계**: 받는 사람이 메시지 파일을 직접 열 수 있고 보낸 사람이 드러난다는 점을 화면에서 미리 알린다.

## 열린 질문

- 사양이 낮은 PC(메모리 8GB 미만)용으로 작은 모델을 따로 둘지는 1단계 사용 결과를 보고 정한다.
- 반응을 보낸 사람에게 돌려줄 때 반응 종류만 보낼지, 짧은 답장까지 허용할지 정해야 한다.
