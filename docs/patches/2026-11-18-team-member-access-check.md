# 팀원 접근·회수 실계정 검증 — 2026-11-18

소유자 계정의 [샘플 분석 1회](2026-11-18-team-ai-live-verification.md) 검증 다음 단계다. 사용자가 지정한 별도 Google 계정으로 **초대 전 차단 → 임시 초대 후 파일 읽기·팀원 역할 확인 → 권한 회수 후 차단**을 실제 검증했다. Google 로그인은 유효한 상태에서 공유 권한만 회수했고, 팀 정책이 켜진 중계에서도 접근이 거부됐다. 종료 후 소유자만 있던 공유 상태와 빈 정책·비공개 중계로 복귀했다. 이번 단계의 추가 Claude 분석 호출은 **0회**다.

## 준비한 검사

| 순서 | 확인할 결과 |
|---|---|
| 초대 전 | 별도 계정의 신원이 맞고 소유자와 다름. 검증 폴더와 합성 파일에 접근할 수 없음 |
| 초대 후 | 지정 계정에만 임시 편집 권한 부여. 기존 136바이트 합성 파일의 본문 해시가 일치함 |
| 팀 AI 연결 | 계정·서비스별 직접 동의 후 상태 조회가 성공하고 `owner: false`, `analysisDisabled: true`임 |
| 권한 회수 후 | 같은 팀원 로그인으로 새 Drive·중계 요청이 거부됨. 팀 전체 사용 중지와 구분해 확인 |
| 종료 | 이번에 추가한 권한만 회수. 빈 허용 목록·비공개 중계로 복귀하고 외부 차단 확인 |

권한 회수 검증은 이후의 Drive·중계 요청 차단을 확인한다. 이미 내려받은 사본은 각 PC에 남는다.

## 유료 분석을 차단하는 중계

`services/team-ai/access-check-worker.mjs`는 운영자 검증용 별도 진입점이다. `POST /v1/status`만 기존 `worker.mjs`에 위임해 동일한 Google 신원·소유자·명시적 팀 권한 검사를 사용한다. 성공 상태는 `ready: false`, `analysisDisabled: true`로 반환한다. 분석 요청은 Google 조회·예산 예약·Claude 호출 전에 `403 / analysis_disabled`로 거부한다.

기본 `wrangler.jsonc`의 일반 서비스 진입점은 유지했다. 계정별 검증 설정은 Git에서 제외된 `target/team-ai-operator/wrangler.access-check.jsonc`에 두었다. 배포 전 빌드와 별도 계정의 로그인·초대 전 차단 확인 뒤 이 진입점을 원격에 일시 배포하고 검증 팀 하나의 정책을 적용했다. 이전에 승인된 유료 분석 1회는 사용 완료 상태이며, 이번 단계에 추가 분석 호출을 포함하지 않는다.

실제 workerd 검사에서 팀원 상태 조회·소유자 구분, 분석 요청 전면 거부, 추가 외부 요청·예산 증가 없음, 권한 철회 후 거부를 확인했다. 외부 API는 모두 가짜 응답을 사용했다.

## 계정 분리와 운영 도구

팀원용 앱은 별도 `SAI_PREVIEW_DIR`에서 실행한다. 소유자 토큰·설정을 복사하거나 기존 로그인에서 로그아웃하지 않았다. 새 창에서 사용자가 지정 계정으로 Google 로그인·동의를 직접 완료했고 읽기 도구와 앱 화면에서 일치를 확인했다.

`core/examples/team_member_check.rs`는 다음을 읽기 전용으로 확인한다.

- 지정한 이메일과 실제 검증 신원의 일치, 소유자와 다른 계정, Drive 권한과 Calendar 권한의 분리.
- 정확한 사이 검증 폴더·소유자·합성 파일·136바이트 본문의 SHA-256.
- 기존 계정·원점별 동의가 있을 때만 `/v1/status`로 토큰 전달. 동의가 없으면 중계 조회를 생략.
- 초대 전·팀원·회수 후의 서로 다른 수용 조건. 전역 사용 중지로 인한 거부는 권한 회수 성공으로 인정하지 않음.
- 실행 전후 앱 설정 해시 일치. 토큰 갱신은 메모리에서만 처리하며 토큰·본문·오류 원문은 출력하지 않음.

`core/examples/team_member_permission.rs`는 지정 소유자·검증 폴더에서만 임시 권한을 관리한다. 소유자만 있는 사전 상태에서 지정 계정의 편집 권한을 추가하고, 의도·신규 권한 ID를 먼저 기록해 결과가 불확실할 때 중복 생성하지 않는다. 회수 시 해당 실행이 만든 동일 계정·동일 폴더의 새 편집 권한인지 다시 확인한다. 기존 권한·소유권·파일은 삭제하지 않는다. Google의 [permissions.create](https://developers.google.com/workspace/drive/api/reference/rest/v3/permissions/create)의 `sendNotificationEmail: false`를 사용해 별도 초대 메일은 요청하지 않으며, 회수는 [permissions.delete](https://developers.google.com/workspace/drive/api/reference/rest/v3/permissions/delete)로 추가한 권한 항목만 대상으로 한다.

두 도구와 계정별 JSON은 개발·운영 검증용이다. 일반 팀원은 앱의 Google 로그인으로 연결한다. 이메일·계정 식별자·허용 정책·진행 기록은 로컬의 제외된 운영 폴더에만 보관한다.

## 완료한 검사와 남은 범위

관련 Node 검사 **43개**, 팀원 읽기 도구 Rust 검사 **4개**, 임시 권한 도구 Rust 검사 **2개**가 통과했다. 검증용 Worker의 배포 전 빌드와 읽기 도구의 Windows x64 개발 빌드도 통과했다.

다음 실계정 결과를 로컬 운영 기록에 저장했다.

- 초대 전: 소유자와 다른 지정 계정의 신원을 확인했다. 검증 폴더·파일 메타데이터는 모두 404였고 중계는 동의가 없어 호출하지 않았다.
- 임시 초대: 소유자만 있던 권한 목록을 확인한 뒤 지정 계정에 편집 권한 하나를 추가하고 재조회했다. 기존 권한은 보존했고 별도 초대 알림 메일은 요청하지 않았다.
- 초대 후: 폴더·파일 메타데이터·136바이트 다운로드가 모두 200이고 원본 SHA-256이 일치했다. 이 읽기 작업 전후 앱 설정 해시가 같았다.
- 앱: 새 Google 로그인 요청 없이 초대받은 팀 목록에서 검증 팀을 선택했다. **함께 쓰는 팀 · 편집 가능**, 합성 파일 목록, 기존 검증 할 일 2개가 표시됐다. 팀원 계정의 개인 팀 참조 저장 외에 팀 자료·Calendar에는 쓰지 않았다.
- 원격 중계: 인증 없는 상태 조회는 401, 자격 증명과 원문 없는 빈 분석 경로 확인은 403 / `analysis_disabled`였다. 이 확인은 Claude 요청을 하지 않았다.

사용자가 해당 계정의 첫 토큰 전달 동의를 직접 완료했다. 저장된 동의를 사용한 상태 조회는 **200**, `owner: false`, `analysisDisabled: true`, `ready: false`였다. 같은 조회에서 검증 파일 다운로드 200과 원본 해시 일치도 다시 확인했다. 이로써 파일 접근뿐 아니라 중계의 실제 Google 권한 검사에서도 소유자가 아닌 팀원으로 허용됨을 확인했다. 사용량 `used: 1`은 앞선 소유자 분석의 기존 일일 기록이며 이번 상태 조회는 분석 예약을 하지 않는다.

## 권한 회수와 종료 확인

저장된 신규 권한 기록과 현재 계정·폴더·역할을 대조한 뒤 이번에 추가한 편집 권한 하나만 회수했다. 소유자의 앱 설정은 보존됐고, 재조회에서 해당 권한이 사라졌음을 확인했다.

빈 정책을 적용하거나 중계를 비공개로 바꾸기 **전**에 같은 팀원 세션으로 다시 조회했다. Google 신원은 정상 검증됐으며 폴더·파일 메타데이터는 각각 **404**, 중계는 **403 / google_access_denied**였다. 전역 사용 중지로 인한 거부를 권한 회수 증거로 사용하지 않았다. 이 읽기 실행에서도 앱 설정 해시는 같았다.

그 뒤 `TEAM_AI_POLICY`의 허용 팀을 비우고 일반 `worker.mjs`를 `workers_dev: false`, `preview_urls: false`로 배포했다. **No targets deployed**, 공개 주소의 **404**, 필수 Secret 세 이름의 보존을 확인했다. 연결 도구로 폴더를 재조회해 기존 소유자 권한 하나만 남아 있음을 확인했다. Secret 원문·개인 AI 키는 읽거나 이동하지 않았다.

앱 화면에서도 해당 팀이 협업 목록에서 빠지고 **연결된 팀이 없어요**로 표시됐다. 프로젝트·할 일 추가와 팀 AI 버튼이 비활성화됐다. 이미 받은 사본의 삭제나 Google 로그인 해제는 수행하지 않았다. 팀 자료·할 일·Calendar에 새 내용을 저장하지 않았다.

검증 결과와 정리 기록은 로컬 운영 폴더에 저장했다. 이 검증의 범위는 **Windows PC 한 대의 분리된 앱 자료 공간, 소유자·직접 초대한 편집 권한 계정, 합성 파일 하나**다. 실제 다른 PC 설치·복원, 읽기 전용 역할·조직 계정·그룹 공유, 팀원 계정의 실제 Claude 분석과 정상 팀 상시 운영은 별도 검증·결정 사항이다. 이번 접근·회수 검증을 제품 전체의 정식 배포 완료로 확대하지 않는다.

## 첫 로그인에서 확인한 Google 접근 제한

첨부된 Google 오류 화면은 테스트 모드의 OAuth 사용자 제한을 명시한다. [공식 동작 조건](https://developers.google.com/identity/protocols/oauth2/production-readiness/overview)과 대조해 개발자 프로젝트의 테스트 사용자 허용 목록을 확인하도록 안내했다. [설정 절차](../../config/README.md#테스트-계정의-google-403-오류)에 Audience → Test users → Add users → Save와 앱에서 새 로그인 시도를 시작하는 방법을 기록했다.

로컬 OAuth 설정에는 프로젝트 ID가 없어 특정 Cloud 프로젝트를 추측하지 않았다. 클라이언트 Secret을 출력하거나 콘솔의 테스트 사용자·공개 상태·클라이언트 키를 변경하지 않았다. 이후 사용자가 접근 설정과 로그인을 완료했다고 보고했고, 실제 지정 계정의 신원 검증이 성공했다. 프로젝트의 실제 허용 목록이나 공개 상태를 직접 조회한 결과는 아니다.
