# 팀 Drive의 협업 기본 기능

기준일: 2026-11-17. 3단계의 작은 후속 패치이며 정식 배포·두 PC 전체 검증 완료를 뜻하지 않는다.

## 사용할 수 있는 동작

**협업 → 연결된 팀 선택 → 프로젝트 또는 할 일 추가 → 팀에 저장**으로 사용한다. 프로젝트는 제목·진행 상태, 할 일은 제목·프로젝트·담당자 표시·마감일·진행 상태를 보관한다. 시작 전·진행 중·완료 상태를 수정할 수 있다. 날짜만 보관하며 Calendar 이벤트는 만들지 않는다. 담당자 이름·이메일 입력은 초대나 Google 접근 권한 변경이 아니다.

팀 목록은 기존 Google 개인 설정에서 복원한 참조를 사용하고, 실제 접근은 현재 Drive 권한으로 확인한다. 파일 화면에서 고른 팀도 협업 선택에 반영한다. 협업 화면을 보는 동안 30초마다 확인하며 편집 중에는 자동 갱신을 멈춘다. 동기화 버튼으로 최신 자료와 전송 대기를 확인한다. 사용자에게 서버·JSON 편집·콘솔 설정을 요구하지 않는다.

## 저장·충돌·복구

- 팀 공유 폴더에 `saiCollab=1` 공개 사용자 속성이 있는 JSON 변경 파일을 추가한다. 앱의 일반 파일 목록과 가져오기 선택에서 내부 기록은 제외한다. 다른 팀의 협업 기록을 일반 파일로 가져오는 것도 차단한다.
- 전체 목록 파일을 수정하지 않고 각 변경을 독립 파일로 저장한다. 항목·변경·앞선 변경 번호와 전체 항목 내용을 보관한다. PC 시각으로 승자를 정하지 않는다.
- 같은 항목의 현재 변경 번호가 편집 시작 때와 다르면 저장을 거부하고 입력을 유지한다. 확인 직후 다른 PC가 동시에 저장하면 두 변경을 보존한다. 화면에서 두 내용을 확인하고 하나를 바탕으로 수정·저장하면 두 변경을 이은 새 기록이 된다. 이전 기록은 삭제하지 않는다. 서로 다른 필드를 고쳐도 같은 항목이면 확인이 필요할 수 있다.
- 계정·팀별 로컬 저장소에 전송 대기를 먼저 원자적으로 저장한다. Google 예약 파일 ID를 기록한 뒤 업로드하고, 응답이 유실되면 같은 ID의 메타데이터·본문을 조회해 확인한다. 확인하지 못한 작업은 공유 완료로 표시하지 않는다. 대기는 동기화로 이어 보낸다.
- 파일 이름·팀 폴더·표시 속성·본문·스키마·변경 그래프를 검사한다. 일부 기록 누락·조회 실패·손상·예상 밖 변경을 빈 목록으로 간주해 덮어쓰지 않는다. 이미 확인한 원격 기록이 없어지면 자동 복원·삭제하지 않고 확인을 요구한다.
- 계정 전환 시 이전 화면·편집을 닫고 오래된 응답을 무시한다. 이전 계정의 대기를 새 계정으로 전송하지 않는다. 읽기 전용 팀은 조회만 가능하며 공유가 취소되면 다음 조회·저장을 거부한다.
- 전송 대기가 남은 팀은 연결 목록에서 제거하지 않는다. 협업 동기화를 먼저 완료해야 한다. 권한이 취소된 상태라면 소유자의 접근 복구가 필요하며, 대기 강제 삭제·내보내기는 이번 UI에 추가하지 않았다.
- 편집 입력은 저장 오류 때 보존한다. 저장 전 창을 종료한 입력까지 복구하지는 않는다. 저장 버튼을 누른 뒤 PC에 보관된 대기는 재시작 후 유지한다.

## 범위와 제한

초기 미리보기는 팀당 항목 128개·변경 기록 512개·로컬 대기 32개를 허용한다. 자동 압축·삭제·이전 자료 자동 가져오기·항목 삭제는 이번 범위에 포함하지 않는다. 한도에 도달하면 기존 기록을 지우지 않고 저장을 멈춘다.

자료는 팀 Drive 권한을 상속하는 일반 JSON 파일이다. 팀 편집자는 Drive에서 기록을 바꾸거나 지울 수 있으므로 앱 화면의 역할 표시를 별도 보안 권한으로 주장하지 않는다. 기록의 암호화·작성자 서명·운영자 접근 불가를 보장하지 않는다. 손상된 기록은 자동 삭제하지 않는다. 실제 Drive에서 수동으로 기록을 편집·이동·복사하는 흐름은 지원하지 않는다.

AI 분석·공용 AI·일정 추출·Google Calendar 쓰기는 아직 연결하지 않았다. 기존 Google 연결을 사용하며 새 OAuth 권한을 추가하지 않는다. 실제 사용자 자료를 자동 테스트로 만들거나 보내지 않는다.

## 검증

자동 검사는 프로젝트·할 일 저장과 다른 로컬 저장소 복원, 동시 변경과 명시적 정리, 오래된 편집 거부, 응답 유실·재시작·예약 ID 재사용, 부분 조회·기록 누락·내용 변경·손상 로컬 저장, 실제 계정 전환의 대기 격리, 읽기 전용·공유 취소·잘못된 파일 메타데이터, 내부 기록 가져오기 차단을 모의 Google API로 확인한다. 이전 Firebase 실계정 검사 3개는 실행하지 않는다.

최종 자동 검사 **141개**(core 135, Windows 앱 4, UI 2)가 통과했다. 대기가 남은 팀 연결 제거 차단과 동기화 후 제거 시 원격 파일 보존도 확인했다. Wasm·Windows x64 빌드를 확인했으며, 가상 자료 UI에서 할 일 입력·저장 후 목록 반영·동시 변경의 두 내용 표시·선택한 내용으로 정리 저장을 확인했다. 실제 사용자 Google 계정에서 자료를 생성·수정하거나 동의를 자동 승인하지 않았다.

실제 두 Google 계정·두 PC에서 생성·수정·동시 수정·권한 취소·재시작 복구를 확인하기 전에는 전체 협업 흐름이 검증됐다고 표시하지 않는다.
