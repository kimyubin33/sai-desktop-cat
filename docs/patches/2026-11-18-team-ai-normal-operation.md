# 팀 Claude 첫 운영 활성화

기준일: 2026-11-18. 사용자가 구체적인 운영 조건을 검토한 뒤 진행을 승인해 **앤드위브 AI 한 팀·서비스/팀 전체 하루 10회로 상시 연결을 활성화**했다. 실제 소유자 세션의 상태 조회와 앱 표시, 미허용 팀의 차단을 확인했다. 이번 추가 Claude 분석은 0회다. 앞선 [소유자 분석 1회](2026-11-18-team-ai-live-verification.md)와 [팀원 접근·회수 검증](2026-11-18-team-member-access-check.md)의 제한된 승인을 자동 확대하지 않고 이번 운영 범위를 별도로 확인했다.

## 선택한 운영 범위

| 항목 | 첫 운영 설정 |
|---|---|
| 허용 팀 | 앤드위브 AI 한 팀. 검증 A·B는 제외 |
| 팀 확인 | 소유자 Google 신원, 실제 폴더 ID·사이 표시·단독 소유자 permission ID를 읽기로 검증 |
| 모델 | 기존 검증을 마친 `claude-sonnet-5-5` |
| 하루 한도 | 서비스 전체 10회, 해당 팀 전체 10회. 팀원별 10회가 아님 |
| 입력·출력 | UTF-8 본문 최대 24KiB, 출력 최대 1,024토큰 |
| 비용 부담 | 이미 Worker Secret에 등록한 Claude API 키의 결제 계정 |
| 접근 | 현재 Google 신원·명시적 팀 공유 권한을 매 요청마다 확인 |
| 공개 범위 | 기존 Worker의 `workers.dev` 연결을 유지. 미허용 팀의 분석은 차단 |
| 실행 | 앱의 계정·원점별 연결 동의와 전송 본문 확인 후 사용자가 분석 실행 |

시도 수는 성공 횟수나 금액의 절대 상한이 아니다. 예약 후 실패·응답 유실도 한도를 소비하며 자동 재시도하지 않는다. UTC 일일 구간, 즉 한국시간 오전 9시에 새 구간을 시작한다. 기존 시도 기록을 지우거나 한도를 새로 충전하지 않는다. 앞선 검증의 전체 서비스 사용 기록이 같은 UTC 날짜에 있으면 첫날 남은 횟수는 10회보다 적을 수 있다.

[공식 Sonnet 5.5 가격](https://platform.claude.com/docs/en/models/sonnet-5-5/overview)은 확인일 기준 입력 100만 토큰당 US$2, 출력 100만 토큰당 US$10이다. 요청별 입력량에 따라 비용이 달라지며 실제 청구액·잔액·제공자 결제 한도는 조회하지 않았다. Cloudflare 운영 비용도 Claude 분석료와 별개다.

Google 비밀번호·refresh token·Calendar 토큰·공용 Claude 키를 팀원 PC에 배포하지 않는다. 다만 Google 접근 토큰은 팀 권한 확인을 위해 중계에 전달되고, 선택 본문은 중계와 Anthropic이 처리한다. 전체 Drive 토큰에 관한 [신뢰 경계](../../services/team-ai/README.md#신뢰-경계)는 그대로 적용된다.

## 활성화 전 준비

- 실제 Google 계정이 선택 팀의 단독 소유자이며 UserInfo·Drive 권한 조회가 정상이다. 읽기 전후 앱 설정 해시가 같았다.
- 운영 초안에 팀 한 개, 서비스·팀 한도 각각 10, 모델과 출력 상한을 반영했다. 실제 폴더 ID와 소유자 ID는 Git에서 제외된 로컬 운영 폴더에만 보관한다.
- 기존 배포 검사로 초안의 7개 구성 항목을 통과했다. **키·서명키는 명시적인 합성 대체값**을 사용했으며 실서비스 Secret 원문을 읽거나 유효성을 다시 검증한 결과가 아니다.
- Wrangler 4.164.0의 `deploy --dry-run`에서 일반 `worker.mjs`와 SQLite 바인딩을 묶었다. 배포·Secret 변경은 하지 않았다.
- 활성화 전 공개 주소의 자격 증명 없는 상태 조회가 404임을 재확인했다.

초안과 증거는 `target/team-ai-operator/`의 `normal-team-owner.json`, `normal-policy.draft.json`, `wrangler.normal.draft.jsonc`, `normal-offline-check.json`, `normal-private-baseline.json`, `normal-operation-plan.json`에 보관한다. 이전 검증용 정책을 정상 운영에 재사용하지 않았다. 기존 연결 정보를 포함한 Windows x64 미리보기를 사용했고 앱을 다시 빌드하지 않았다.

## 적용과 확인

1. 위 팀·한도·모델·기존 키의 비용 부담과 지속적인 공개 연결을 제시한 뒤 사용자의 다음 진행 승인을 받았다. 추가 유료 검증 분석은 실행하지 않았다.
2. 실제 소유자와 승인된 정책·배포 초안의 SHA-256을 다시 대조했다. 기존 `ANTHROPIC_API_KEY`와 `AI_HMAC_KEY`를 보존하고 `TEAM_AI_POLICY`만 표준 입력으로 갱신했다. 비밀값을 출력하거나 명령 인자로 넣지 않았다.
3. 일반 `worker.mjs`, 필수 Secret 세 이름, 기존 SQLite 마이그레이션을 유지한 운영 초안으로 공개 배포했다. 상태 조회 전용 진입점을 사용하거나 사용 기록·서명키를 초기화하지 않았다.
4. 기존 소유자 로그인과 계정·원점별 동의를 사용해 아래 상태 조회를 수행했다. 새 동의·로그인·분석은 시작하지 않았다.
5. 앱에서도 파일 화면의 앤드위브 AI 카드 → 협업을 열어 **팀 Claude 사용 설정을 확인했어요. 일일 한도 0 / 10회 요청했어요.** 표시를 확인했다. 검사 도구의 드롭다운 선택과 접근성 위치 정보가 안정적이지 않아 실제 화면의 파일 카드를 이용했다. 팀 선택 메뉴의 조작 안정성은 추가 확인 대상이다.

| 조회 | 실제 결과 |
|---|---|
| 허용 팀 첫 상태 조회 | 200, `owner: true`, `ready: true`, `dailyRequests: 10`, `used: 0` |
| 검증 A 팀 상태 조회 | 403, `team_not_enabled` |
| 허용 팀 반복 조회 | 200, 사용 횟수 0 유지 |

읽기 전용 개발 도구 [team_ai_status_check.rs](../../core/examples/team_ai_status_check.rs)는 기존 계정·원점별 동의와 예상 Google 신원을 먼저 확인한다. Calendar 권한이 섞인 토큰, 경로·인증 정보가 있는 주소, 잘못된 팀 비교를 거부하며 리디렉션을 따라가지 않는다. 요청 경로는 `POST /v1/status`로 고정하고 본문·응답 크기를 제한한다. 원문·토큰·키를 출력하지 않는다. 목적지 제한과 거짓 성공 판정 방지 등 **자동 검사 4개**가 통과했다. 실계정 조회 전후 앱 설정 해시는 같았다.

필수 Secret 이름 세 개의 배포 전후 보존도 확인했다. 실제 Secret 값은 읽지 않았다. 배포 버전과 정책·설정 지문, 상태 결과, Secret 이름 확인 기록은 로컬 운영 폴더의 `normal-activation-attempt.json`, `normal-owner-recheck.json`, `normal-status-plan.json`, `normal-status-result.json`, `normal-secrets-before.json`, `normal-secrets-after.json`, `normal-activation-result.json`에 남겼다. 이번 추가 Claude 분석·협업 저장·Calendar 등록은 각각 0회다. `ready`는 연결 설정 확인값이며 이번 실행에서 제공자 모델을 유료로 다시 호출해 검증한 결과는 아니다.

운영을 중지하거나 활성화 확인에 실패하면 `empty-policy.json`으로 허용 팀을 비우고 `wrangler.private.jsonc`의 비공개 일반 진입점으로 되돌린다. 외부 상태 조회 404와 필수 Secret 이름 보존을 확인하고 결과를 기록한다. 이번에는 연결 확인이 통과해 승인된 공개 연결을 유지한다. 이미 전송된 요청·발생한 비용을 취소하거나 초기화한다고 보장하지 않는다.

## 다음 검증

이번에는 상시 활성화와 소유자의 연결 상태를 확인했다. 앞선 두 계정 검증의 범위는 한 PC에서 팀원의 접근·회수였다. 다음 설치 검증은 새 PC에서 Google 로그인 → 팀·설정 복원 → 파일·협업 조회를 확인하며 이전 PC의 로그인 토큰을 복사하지 않는다. 실제 팀원 분석, 읽기 전용 역할, 새 PC Calendar 연결과 정식 배포는 아직 완료되지 않았다.
