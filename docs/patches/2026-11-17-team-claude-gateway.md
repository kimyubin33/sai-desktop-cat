# 팀 Claude 중계와 연결 기반

기준일: 2026-11-17. 사용자는 기존 Claude 연결을 이어 쓰기로 선택했다. 4단계의 첫 기반 패치이며 실제 팀 AI 사용·배포 완료를 뜻하지 않는다.

## 이번 범위

- 개발·운영 측 Worker 중계와 Durable Object 시도 한도. Google의 실제 계정·팀 권한과 등록한 소유자를 확인한다.
- 공용 Claude 키는 서비스 Secret에서만 읽는다. 기존 개인 키를 꺼내거나 전송하지 않았고, 키 원문을 팀원 PC·Drive에 배포하지 않는다. OpenAI 키를 새로 만들지 않았다.
- 앱은 빌드에 포함한 HTTPS 원점만 사용한다. 협업 칸에서 팀 Claude 연결 상태를 확인하고 미배포 상태를 준비 중으로 표시한다. 일반 사용자용 서버 주소·키 입력은 추가하지 않았다.
- access token 전달 전 Drive 전체 권한이 포함됨을 명시하고 한 번 동의받는다. 동의는 이 PC의 계정·원점별로 기록한다. 동의 전 중계로 토큰을 보내지 않는다. 작업마다 Google 로그인 창을 다시 열지 않는다.
- 분석 요청 계약과 근거·날짜·잘린 응답 검증을 추가했다. 24KiB 이하 텍스트와 12개 이하 후보만 처리한다. 도구·Drive 쓰기·Calendar 작업은 제공하지 않는다. 분석 IPC와 파일 분석 버튼은 아직 노출하지 않았다.

운영자가 유효한 access token으로 전체 Drive 권한을 사용할 수 있다는 신뢰 경계가 남는다. 운영자 접근 불가·종단 간 암호화·선택 파일로 축소한 토큰을 보장하지 않는다. 실제 파일 분석 화면에서도 처리 서비스와 전송 범위를 먼저 안내해야 한다.

## 다음 단계와 검증 경계

배포 위치·비용 책임·예산·모델과 Secret 등록은 결정·승인 전이다. Cloudflare 런타임·실제 Google 두 계정·실제 Claude 호출 검증도 남아 있다. 이번 개발에서 배포·키 이동·과금 호출을 하지 않았다. [운영 계약](../../services/team-ai/README.md)을 따른다.

다음에는 파일/텍스트 선택·전송 범위 확인, 근거·불명확한 날짜/담당자 검토, 확인한 후보만 안정적인 업무 번호로 저장하는 화면을 연결한다. 이를 현재 사용 가능한 기능으로 표시하지 않는다.

## 검증

Rust 전체 검사 151개(core 145, Windows 앱 4, UI 2) 통과 후 추가 계정 전환 검사를 포함한 관련 검사 11개와 Node 모의 검사 17개를 확인해, 최종 자동 검사 범위는 **169개**다. 본문·Google 토큰·Claude 키의 목적지 분리, 명시적 팀원과 소유자 확인, 동시 중복·한도·응답 유실·서버 재시작·UTC 날짜 변경·지문 키 교체, 잘린 응답·임의 근거·날짜·추가 실행 필드, 동의 전 전송 차단·계정/원점별 동의 복원·리디렉션 차단을 확인했다. 이전 Firebase 실계정 검사 3개는 실행하지 않았다. Worker 진입점 문법과 Wasm·Windows x64 빌드를 확인했다. 가상 자료 화면에서 연결 상태·한도 표시를 확인했다. 실제 Cloudflare 런타임과 과금 API 동작을 확인한 것은 아니다.
