# Google 작업 공간 검증판 마무리

기준일: 2026-11-18. 사용자가 다른 PC의 복원 검증을 나중으로 미루고 마무리를 요청했다. **현재 구현을 검증판 체크포인트로 보관**하며 실제 다른 PC 검증을 완료로 표시하지 않는다.

## 정리한 사용자 흐름

**설치 → Google 로그인 → 팀·파일 → 협업 → 검토한 AI 업무 → 내 일정**을 현재 구현의 기준으로 유지한다. 톡·PC 서버·LAN 연결과 일반 사용자의 서버 설정은 제거했다. 이전 자료는 원본을 보존하고 선택 내보내기로 다룬다.

Google 계정의 팀·이름·기본 설정은 개인 Drive 앱 공간, 팀 파일과 협업은 팀 Drive 폴더에 보관한다. 공용 AI 키는 운영 서비스 Secret에 두며 실제 Google 팀 권한과 한도를 확인한다. Calendar는 별도 동의와 본인 계정으로 처리한다. AI 결과·일정은 검토한 범위에서 저장하며 자동 분석·자동 일정 등록을 추가하지 않았다.

마무리 점검에서 다음 두 안내를 수정했다.

- 설정의 오래된 **팀 AI는 준비 중** 문구를 **팀 AI의 연결 상태는 협업 화면에서 확인**으로 바꿨다. 현재 연결 상태를 단정하는 정적 안내를 없앴다.
- 화면 시작 시 직접 지정한 접근성 이름을 유지한다. 계정 설정 버튼의 이름이 최초 Google 로그인 문구로 덮어써지는 문제를 수정했다.

## 전체 자동 검사

- Rust 작업 공간·모든 대상 검사 **216개 통과**. Google 복원·계정 전환·파일·협업·AI·Calendar와 개발용 읽기 도구를 포함한다. 과거 Firebase 실계정 검사 3개는 기존처럼 제외했다.
- Node 중계·SQLite 런타임·배포 설정·설치 패키지 검사 **43개 통과**.
- 합계 **259개 통과, 실패 0개**다. 실제 외부 계정·유료 AI 호출을 사용하지 않았다.

Rust 명령은 `cargo test --locked --workspace --all-targets --target x86_64-pc-windows-msvc -- --test-threads=4`다. Node 검사는 `gateway.test.mjs`, `check-deployment.test.mjs`, `runtime.test.mjs`, `check-google-client.test.mjs`, `build-preview.test.mjs`를 실행했다. Windows ARM64 개발 PC에서 Rust·workerd는 기존 x64 도구로 확인했다.

전체 변경 파일을 대상으로 비밀키 형식과 로컬 운영 계정·폴더 식별자의 포함 여부를 점검했다. 앱 로그인 설정 원문·토큰 저장소·Claude 키·로컬 운영 정책·실행 로그는 Git에 넣지 않는다. 실제 비밀값을 출력하지 않았다.

## 설치 파일과 보관

수정된 화면을 포함한 Windows x64 독립 미리보기의 **Wasm·릴리스·NSIS 빌드를 완료**했다. 처음에는 실행 중인 검증 앱 때문에 최종 배포 사본 복사가 막혔다. 두 검증 창에 미완료 입력이 없는 것을 확인해 정상 종료한 뒤, 이미 성공한 빌드 결과를 다시 수집했다. 최종 실행 파일·체크섬·빌드 정보가 서로 일치함을 확인했다.

새로 분리한 빈 PC 자료 공간으로 최종 실행 파일을 열어 초기 Google 로그인 안내, **계정 설정 열기** 접근성 이름과 수정한 팀 AI 안내를 확인했다. Google 로그인·설정 저장은 하지 않았고 확인 후 정상 종료했다. 실제 다른 PC에서 로그인·복원을 검증한 결과는 아니다.

최종 묶음은 `target/Sai-Preview-Checkpoint-20261118-win-x64.zip`이며 **7,927,327바이트**다. SHA-256은 `7902ceb5727903c9701e0289e36c9c66305a88d7f4cd489e4e973b536b94cc1c`이고 옆의 `.zip.sha256` 파일에도 기록했다. ZIP을 다시 열어 다음 다섯 항목의 목록·크기·해시를 원본과 대조했다.

| 항목 | 내용 |
|---|---|
| `Sai-Preview-Setup-0.9.14.exe` | 독립 미리보기 설치 파일 |
| `Sai-Preview-Portable-0.9.14.exe` | 같은 검증판의 포터블 실행 파일 |
| `SHA256SUMS.txt` | 두 실행 파일의 SHA-256 |
| `preview-build.json` | 미리보기 식별자·CPU·버전·연결 정보 포함 여부 |
| `먼저 읽어주세요.txt` | 간단한 설치·Google 로그인 안내 |

개인 자료·로그인 토큰·키 파일은 묶음에 넣지 않았다. 설치 파일의 코드 서명 상태는 기존과 같은 `NotSigned`다. 생성물은 로컬에 보관하며 소스 커밋에 바이너리·개인 설정을 포함하지 않는다. 빌드·묶음·화면 확인 결과는 Git에서 제외한 `target/final-preview-checkpoint-result.json`에 기록했다.

소스는 `work/google-workspace-preview-20261118` 작업 브랜치에 보관한다. 미리보기 앱 ID·이름·자료 공간은 기존 사이와 분리하고 시작 프로그램·정식 자동 업데이트는 사용하지 않는다. 소스 보관과 정식 Releases 발행은 구분한다.

## 유지되는 운영 상태

[공용 Claude](2026-11-18-team-ai-normal-operation.md)는 승인된 **앤드위브 AI 한 팀·서비스/팀 전체 하루 10회**, 기존 모델·출력 1,024토큰으로 연결을 유지한다. 이번 마무리에서 운영 정책·API 키·서명키·기존 사용 기록을 변경하지 않고 추가 유료 분석·Drive 변경·업무 저장·Calendar 등록을 실행하지 않는다.

## 보류와 남은 범위

[다른 PC의 실제 설치·Google 로그인·팀·설정·파일 복원](2026-11-18-new-pc-restore-check.md)은 **사용자 요청으로 보류**했다. 지금 이 결과를 다시 요구하거나 기다리지 않는다. 나중에 재개할 때 최신 체크포인트 설치 파일을 사용한다.

실제 팀원 AI 분석, 읽기 전용 등 다른 역할, 다른 CPU·네트워크·설치 실패 경로와 운영 지속성은 남아 있다. 팀 선택 드롭다운의 검사 도구 조작도 안정적으로 확인하지 못했다. 기존 파일 카드 경로의 팀 선택과 협업 연결 상태는 확인했다. 이 범위를 새 PC·모든 계정의 제품 검증 완료로 확대하지 않는다.

Calendar의 실제 수정·삭제·동시 처리와 자동화, 코드 서명·정식 업데이트·정식 배포도 후속 범위다. 사용자가 마무리를 요청한 것은 이 미검증 항목의 통과 증거가 아니다.
