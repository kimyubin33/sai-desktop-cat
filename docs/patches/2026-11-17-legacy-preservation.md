# 두 번째 패치 — 이전 자료 보존과 선택 내보내기

2026-11-17. [개발 계획](../development-direction.md) 1단계의 남은 자료 보관 작업이다. 1단계의 구현·로컬 검증을 마치며, Google 팀 복원이나 정식 배포 완료를 의미하지 않는다. 버전은 v0.9.14로 유지한다.

## 사용하는 방법

설정의 **이전 자료 보관**을 펼치면 이 기기에 남아 있는 팀·프로젝트·업무·파일 링크 수를 확인할 수 있다. **자료 내보내기**는 새 JSON 사본을 만들고 **저장 폴더 열기**를 제공한다. 필요하면 **원본 폴더 열기**로 기존 보관 위치를 확인한다. 일반 파일·AI 화면에 보관용 버튼을 추가하지 않는다.

사본은 앱 자료 폴더의 `local-exports/`에 저장한다. 외부 서비스에 업로드하거나 새 Google 팀으로 가져오는 동작은 없다. 같은 이름으로 기존 사본을 덮어쓰지 않는다. 실제 파일을 다운로드하는 기능이 아니라 현재 PC에 캐시된 자료의 선택 사본이다.

| 포함 | 제외하고 원본에 유지 |
|---|---|
| 이전 팀 ID·이름·내 표시 이름 | Google/Firebase 로그인 토큰, OAuth 연결 설정, API 키 설정 |
| 캐시된 팀원의 ID·표시 이름 | 팀 참여 코드, 서버 주소, 장치 인증 자료 |
| 프로젝트와 업무의 주요 항목 | 개인·팀 대화 본문, AI 공유 문안·발신 대기함 |
| 캐시된 파일의 이름·링크·Drive ID 등 | 파일 원본, 개인 대화 기록, PC 톡 SQLite·암호화 키 |

고정 서버 전환 전후의 캐시는 보관 출처별로 나눠 읽는다. 같은 팀 ID가 있어도 합치지 않는다. 설정에서 빠진 캐시나 프로젝트 메타데이터가 없는 업무·파일 목록도 선택 사본에 남긴다. 개인 프로필·업무의 추가 필드까지 완전히 복원하는 백업 형식은 아니다. 알 수 없는 항목과 제외된 항목은 원본 파일에 그대로 남긴다.

사본에는 팀 이름·업무 내용·파일 링크가 들어 있다. 공유할 때는 사용자가 내용을 먼저 확인한다. 사용자가 업무 본문에 직접 적은 비밀까지 자동 탐지·삭제한다고 보장하지 않는다.

## 원본 보존 처리

- 앱에서 사용하는 비활성 Hub는 메모리 저장소만 사용한다. 시작 시 이전 팀 캐시를 다시 저장하지 않는다.
- Google 연결 상태는 `private/google-connection.json`에 분리한다. 로그인 상태 기록으로 기존 `shared/team-cache.json`을 덮어쓰지 않는다. 연결 상태 캐시가 손상돼도 로그인·로그아웃 자체를 막지 않는다.
- 저장 파일이 읽기 실패·손상·잘못된 최상위 형식이면 원본을 보호하고 저장을 차단한다. 기본값을 원본 위에 저장하지 않으며 설정에 경고를 표시한다. 자동 복구나 새 파일로 교체하는 기능은 추가하지 않았다.
- 설정·개인 대화 변경의 IPC는 읽기 오류와 저장 실패를 확인한다. 저장하지 못한 작업을 완료로 표시하지 않는다. 기존 개인 대화의 보관 기간 정책은 그대로다.
- 내보내기는 허용한 필드만 새로 구성한다. 연동 객체를 통째로 복사하지 않으며, 선택한 항목의 값이 예상과 다른 중첩 객체여도 그대로 전달하지 않는다.
- 원본 JSON이 손상되었거나 지원 형식이 아니면 빈 사본을 성공으로 만들지 않는다. 파일당 32 MiB, 읽은 원본 총 128 MiB, 보관 출처 128개 제한을 두고 앱 자료 폴더 밖의 경로는 거부한다.
- 저장 중 실패하면 완료 안내를 하지 않는다. 완성 전 파일은 `.partial`, 완성 파일은 `.json`으로 구분한다. 최종 파일 생성에 하드 링크를 사용하므로 이를 지원하지 않는 파일 시스템에서는 오류를 표시하고 원본을 유지한다.

## 확인한 결과

- 기존 Windows 설치 폴더의 파일 6개를 읽기 전후 SHA-256으로 비교했다. 바뀐 파일이 없었다. 해당 설치의 팀 목록은 비어 있었으므로 팀이 있는 경우의 검증과 구분한다.
- 가짜 팀·프로젝트·업무·파일 링크와 가짜 인증·대화 항목을 넣은 별도 폴더에서 실제 Windows UI로 내보내기를 실행했다. 완료 안내와 JSON 사본 생성을 확인했다. 원본 파일 5개의 SHA-256이 모두 같았으며 제외 대상 표식이 사본에 포함되지 않았다. 실제 사용자의 자료는 내보내지 않았다.
- 새 자동 검사 7개: 선택 필드·중첩 인증 값 제외, 이전 사본과 원본 보존, 다중 서버·동일 ID 구분, 고립된 업무 보존, 손상·초과 크기·지원하지 않는 형식 거부, 경로 경계, 오류 저장소의 덮어쓰기 차단, 별도 Google 연결 상태와 알 수 없는 기존 설정 보존을 확인했다.
- 전체 Windows x64 테스트 **63개 통과**, 실제 Firebase 검사는 기존의 **3개 제외**다. WebAssembly 화면 빌드와 Windows x64 앱 빌드도 통과했다.
- Google 실계정 로그인, 팀 초대·복원, Drive 파일 공유, AI 제공자 호출, Calendar 쓰기는 이 패치의 검증 대상이 아니다.

읽기 전용 재검사 도구는 개발용 `cargo run -p sai-core --example check_legacy_archive -- <기존 앱 자료 폴더>`다. 자료 내용이나 인증 값은 출력하지 않으며 네트워크를 사용하지 않는다. 일반 사용자가 실행할 필요는 없다.

## 다음 단계

2단계에서 검증된 Google 계정 식별자와 최소 권한 로그인부터 구현한다. 이름·설정·팀 폴더 참조를 개인 앱 공간에 저장하고, 새 PC의 빈 상태가 원격 목록을 지우지 않게 한다. 이전 Firebase 팀·톡 자료와 이번 로컬 사본은 Google 팀으로 자동 게시하거나 자동 복원하지 않는다.
