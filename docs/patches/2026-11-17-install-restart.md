# 설치·재실행·재설치·제거 확인 — 2026-11-17

실제 x64 Setup을 작업 폴더의 전용 경로에 설치하고, 설치된 앱 화면에서 설정 저장과 종료·재실행을 확인했다. 수정한 Setup으로 다시 설치한 뒤 설정 복원을 확인하고 테스트 설치를 제거했다. **이 ARM64 Windows 개발 PC에서 x64 앱을 실행한 결과**이며, 새 PC·네이티브 x64 PC·ARM64 앱의 검증을 대신하지 않는다.

## 확인한 동작

| 항목 | 결과 |
|---|---|
| 첫 설치 | 현재 사용자용 NSIS가 종료 코드 0 반환. 실행 파일·제거 프로그램·전용 설치 등록 확인 |
| 초기 화면 | Google 시작 안내와 로그인 전 팀 미연결 상태 표시. 서버·JSON 입력 요구 없음 |
| 설정 저장 | 자격 증명 없는 테스트 프로필에서 Claude 모델 문자열을 바꾸고 **변경 저장** 성공 확인 |
| 창 닫기 | 설치된 앱의 창을 닫으면 프로세스 종료. 파일에도 저장한 모델과 AI 꺼짐 상태 유지 |
| 수정판 재설치 | 같은 전용 경로에 새 Setup 설치, 종료 코드 0. 설정 파일의 SHA-256 유지 |
| 재실행 화면 | 저장한 모델 문자열 복원과 기존 빈도·보관 설정 표시 확인. Google·AI 호출 없음 |
| 불필요한 버튼 | 자동 업데이트가 지원되지 않는 실행에서는 **업데이트 확인**을 숨김. 설명은 유지 |
| 기본 제거 | 데이터 삭제 옵션 없이 제거 프로그램 실행, 종료 코드 0. 앱 실행 파일·설치 등록 제거, 테스트 설정 유지 |
| 기존 자료 보호 | 재설치·제거 전후 기존 미리보기 Roaming/Local 파일의 이름·크기·수정 시각 지문 유지. 정식 사이의 시작 프로그램 값 지문 유지 |

설치 대상은 `target/preview-install-check/app`, 앱 자료는 별도의 `target/preview-install-check/profile`로 한정했다. 설치 전 기존 미리보기 설치 등록이 없음을 확인했고, 바로가기를 만들지 않는 옵션으로 실행했다. 재설치·제거 전에 소유 표시 파일과 실제 등록 위치·절대 경로가 작업 폴더 안의 테스트 경로인지 대조했다. 제거 후 테스트 경로를 가리키던 설치 위치 값만 정리했다. 기존 사이와 기존 미리보기 자료 폴더는 제거 대상으로 사용하지 않았다.

설치·제거는 명령줄로 시험했고, 앱 화면은 컴퓨터 사용 도구로 검사했다. [이전 패치](2026-11-17-preview-installer.md)의 새 앱 제어 승인 시간초과는 이번 설치판 검사에서는 재현되지 않았다. Google 로그인·권한 창·Windows 보안 경고는 조작하지 않았다. 대화 보관 같은 개인정보 설정도 화면에서 변경하지 않았다.

처음 넣은 테스트 JSON은 PowerShell의 UTF-8 BOM 때문에 읽기 보호 상태가 됐다. 앱이 원본을 덮지 않았음을 확인하고 **검사 자료만** BOM 없는 UTF-8로 고쳤다. 저장소의 손상 감지나 원본 보호를 완화하지 않았다. 이는 설치 실패나 실제 사용자 설정 손상이 아니다.

## 설치 파일 무결성 검사 보완

설치된 앱과 포터블판을 단순 해시로 비교하면 이번 패키지에서는 3바이트가 달랐다. Tauri는 NSIS에 넣을 때 첫 `__TAURI_BUNDLE_TYPE_VAR_UNK`를 `__TAURI_BUNDLE_TYPE_VAR_NSS`로 바꾸고, 포터블 출력에는 원본을 복원한다. [공식 번들러 소스](https://github.com/tauri-apps/tauri/blob/dev/crates/tauri-bundler/src/bundle.rs)의 처리와 로컬 실행 파일의 차이가 일치했다.

`installedMatchesPortable`은 완전히 같은 파일 또는 **위 첫 표시만 바뀐 파일**만 일치로 처리한다. 실제 파일을 수정하지 않고 메모리에서 전체 바이트를 비교한다. 다른 위치·다른 표시·추가 변경·길이 차이는 거부한다. 이번 설치판과 수정 후 재설치판 모두 이 검사에 통과했다. 길이나 CPU만 같다는 이유로 통과시키지 않는다.

## 검증과 결과물

- `node --test scripts/build-preview.test.mjs scripts/check-google-client.test.mjs`: **10개 통과**, 그중 위 무결성 검사 **3개 신규**다.
- Wasm·Windows x64 릴리스·NSIS 빌드를 통과했다. 실제 설치된 수정판의 화면에서 저장 값 복원과 업데이트 버튼 제거를 확인했다. 두 실행의 오류 로그는 0바이트였다.
- Google·핵심 저장·AI 중계 코드는 바꾸지 않아 해당 전체 회귀 검사를 다시 실행하지 않았다. 화면 수정은 실제 설치판으로 확인했다.
- `target/preview-install-check/`에 설치·설정·수명 주기 검사 결과를 남겼다. 가짜 프로필을 사용했고 자격 증명·사용자 자료 본문을 결과에 넣지 않았다.
- 배포 사본의 SHA-256과 새 ZIP의 항목을 확인했다. 새 ZIP에는 설치판·포터블판·체크섬·빌드 정보·사용 안내 5개만 들어 있다.

| 최신 로컬 파일 | 크기 |
|---|---:|
| `target/preview-dist/win-x64/Sai-Preview-Setup-0.9.14.exe` | 3,502,304바이트 |
| `target/preview-dist/win-x64/Sai-Preview-Portable-0.9.14.exe` | 12,022,784바이트 |
| `target/Sai-Preview-win-x64.zip` | 7,926,657바이트 |

ZIP 자체 체크섬은 `target/Sai-Preview-win-x64.zip.sha256`이다. 파일 경로와 버전은 이전 검증판과 같지만 업데이트 버튼 수정이 포함된 새 빌드로 교체했다. 코드 서명·팀 AI 배포·GitHub 업로드·정식 릴리스는 하지 않았다.

## 남은 실제 검증

실제 Google 계정으로 로그인·팀 복원·Drive 업로드/사본/다운로드·협업 충돌·Calendar 변경과 권한 철회를 확인해야 한다. 다른 Google 계정·실제 두 PC·서로 다른 네트워크도 별도다. 일반 설치 화면·기본 설치 위치·바로가기·새 PC의 WebView2 설치·자동 업데이트·새 버전으로의 이전·네이티브 CPU별 확인까지 완료한 것으로 표시하지 않는다. 공용 Claude는 미배포 상태다.

명령줄 근거: [NSIS의 `/S`·`/D` 규칙](https://nsis.sourceforge.io/Docs/Chapter3.html). 바로가기 제외 `/NS`와 데이터 보존·제거 범위는 로컬 생성 NSIS 스크립트를 확인했다.
