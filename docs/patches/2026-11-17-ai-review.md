# 파일에서 검토한 할 일까지 — 2026-11-17

## 이번 패치

4단계 팀 Claude 중계 기반 위에 **자료 선택 → 전송 본문 확인 → AI 분석 → 근거와 할 일 검토 → 선택한 항목만 협업 저장**을 연결했다. 5단계의 업무 추출과 안정적인 저장을 먼저 구현한 범위다. Calendar 등록은 포함하지 않는다. 중계는 여전히 미배포이며 실제 키 이동·유료 API 호출은 하지 않았다.

### 사용자 흐름

1. 파일 화면에서 팀을 연다. 지원 파일의 **AI로 정리** 또는 **AI로 할 일 정리**를 누른다. 협업 화면의 **내용으로 할 일 정리**에서도 텍스트를 입력할 수 있다.
2. 실제 전송할 텍스트 전체를 읽기 전용으로 확인한다. 전송 내용과 처리 서비스에 동의한 뒤 분석한다. 첫 중계 연결의 Google access token 전달 동의는 별도로 유지한다.
3. 요약과 할 일 후보를 확인한다. 후보마다 원문에 포함된 근거를 표시하고, 제목·담당자·마감일을 수정할 수 있다. 불확실한 항목은 확인 필요로 표시한다. 선택은 기본으로 꺼져 있다.
4. 프로젝트와 공유할 항목을 고르고 공유를 확인한다. 선택한 할 일만 팀 Drive의 기존 협업 변경 기록으로 저장한다. 원문·요약·근거 인용은 자동 저장하지 않는다. 읽기 전용 팀은 분석 결과를 볼 수 있지만 공유할 수 없다.

### 지원 형식과 전송

- Google 문서는 Drive의 `text/plain` 내보내기로 읽는다. 일반 UTF-8 TXT·MD·CSV도 지원한다. UTF-8 BOM은 제거하고 실제 보낼 본문을 표시한다.
- 입력과 파일 본문은 **24KiB(24,576바이트)**까지다. 글자 수와 같지 않다. 응답 길이와 수신 도중 크기를 모두 검사하며, 큰 문서의 앞부분만 조용히 보내지 않는다.
- PDF·DOCX·이미지·Sheets·Slides·OCR은 이번 범위가 아니다. 필요한 부분을 텍스트로 붙여 넣을 수 있다. 일반 파일 받기의 25MB 한도와 분석 한도는 다르다.
- 현재 팀 폴더 바로 안의 지원 파일만 읽고, 다운로드 제한·원본 버전·현재 팀 권한을 미리보기 전후와 분석·저장 시 확인한다. 바뀐 자료나 취소된 권한으로 진행하지 않는다.
- 앱 빌드에 포함한 HTTPS 중계만 사용한다. 화면에서 중계 주소나 공용 키를 받지 않는다. 선택한 본문은 사이 중계와 Anthropic이 처리한다. Google 토큰의 전체 Drive 권한과 운영자 신뢰 경계는 [운영 계약](../../services/team-ai/README.md)을 따른다.

### 호출·저장·중복 처리

- `analysis:prepare`는 본문과 현재 권한을 확인하고 메모리 미리보기를 만든다. 유료 분석을 호출하지 않는다. `analysis:run`은 확인된 세션 번호만 받고, `analysis:commit`은 결과의 유효한 후보 번호와 검토한 필드만 받는다.
- 분석 시작 전에 계정별로 자료 지문·요청 번호·시각·완료 여부를 로컬 기록한다. 최근 최대 512개 시도 메타데이터만 보관하며 원문·결과·토큰·키는 이 기록에 넣지 않는다. 손상된 기록은 덮어쓰지 않는다.
- 같은 세션의 성공 결과는 메모리에서 재사용한다. 실패·응답 유실 때 자동 재호출하지 않는다. 새로 열어 분석하려면 이전 시도와 재과금 가능성을 확인해야 한다. 잃어버린 응답을 중계에서 복구하는 기능은 없다.
- 원문과 결과는 최대 4개 세션의 메모리에만 둔다. 세션은 준비·분석 성공 기준 30분간 사용할 수 있고, 다음 준비 때 만료 세션을 정리한다. 명시적 닫기·로그아웃·프로세스 종료에도 정리한다. 메모리의 보안 삭제나 시스템 덤프까지 차단하는 보장은 아니다. 분석 중 창을 닫아도 이미 보낸 요청의 취소·환불을 보장하지 않는다.
- Drive 파일은 **팀 폴더 ID + 파일 ID**, 직접 입력은 **팀 폴더 ID + 공백을 정규화한 텍스트**로 자료 그룹을 정한다. 등록한 할 일이 있으면 새 분석·추가 등록을 막는 보수적인 첫 구현이다. 같은 파일이 수정돼도 별도 신규 업무로 복사하지 않는다. 기존 할 일은 협업에서 수정한다. 변경된 문서의 신규 업무를 찾아 병합하는 증분 분석은 후속 범위다.
- 선택된 항목에 안정적인 ID를 부여하고, 검증된 묶음 전체를 로컬 대기에 원자적으로 저장한다. 전송 실패는 기존 협업의 예약 파일 ID와 대기로 이어 보낸다. 두 PC의 첫 등록이 겹치면 동일 ID의 동시 변경으로 보존하고 사용자 검토로 정리한다. 의미가 같은 다른 자료나 수동 업무까지 자동 중복 판정하지 않는다.

## 검증

- `cargo test --locked --workspace --target x86_64-pc-windows-msvc -- --test-threads=4`: **168개 통과**(core 162, native 4, UI 2). 이전 Firebase 실계정 검사 3개는 제외 상태다.
- `node --test services/team-ai/gateway.test.mjs`: **17개 통과**. 전체 자동 검사 합계 **185개**다.
- 새 검토 흐름 검사 16개: 정확한 미리보기, Google 문서 내보내기, 초과 크기·미지원 형식·잘못된 UTF-8, 동의·배포 누락, 한 번 호출, 선택 필드만 저장, 미선택 제외, 두 로컬 저장소의 중복 차단, 수정 파일 그룹 유지, 응답 유실·재시작 경고, 위조 선택·프로젝트 검증, 불확실한 저장 재시도, 권한·원본 변경, 계정·팀·닫기 격리, 손상된 시도 기록 보존을 확인했다. 외부 서비스는 모두 모의 서버다.
- `cargo run --locked -p xtask --target x86_64-pc-windows-msvc -- ui`와 Windows x64 네이티브 개발 빌드를 통과했다.
- 자격 증명 없는 로컬 Chrome 가상 자료 화면에서 파일별 진입, 정확한 본문 표시, 동의 전 분석 비활성화, 근거·편집 필드, 기본 미선택, 한 건 선택·공유 확인·저장, 재저장 비활성화와 협업 반영을 확인했다. 실제 Google·Claude 연결을 검증한 결과가 아니다.

## 남은 범위

실제 모델·예산·서비스 운영 위치와 배포 결정, Google 실계정 두 PC의 파일 내보내기·권한 변경·공유 저장, Cloudflare 실행 환경·실제 Claude 호출·응답 유실 검증이 남아 있다. 현재 미리보기 빌드에는 중계 주소가 없어 본문 미리보기까지만 사용할 수 있다. 실제 분석을 사용할 수 있는 릴리스로 표시하지 않는다. 다음 Calendar 작업도 각 사용자의 명시적 권한과 등록 확인을 별도로 구현한다.
